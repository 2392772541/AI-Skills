# 内容关系图表选型

本规则吸收 `cathrynlavery/diagram-design` 的“先判断语义关系，再选择视觉类型”方法。目标不是多画图，而是让读者更快看懂文字难以表达的关系。

## 一、先判断是否值得画

只有满足至少一项时才画：

- 三个以上概念之间存在因果、先后、层级、分支、反馈或依赖关系；
- 一个操作有多个角色、阶段、状态或交接点；
- 读者仅靠段落或三列表格很难在十秒内形成整体结构；
- 课程包含可复现的系统、流程、路线、时间演化或判断逻辑。

以下情况不画：纯列表、简单前后对比、单一结论、一个框就能说完的概念。此时使用正文或表格更清楚。

## 二、关系到图表的映射

| 内容关系 | 优先图表 | 适用场景 | 不适用信号 |
|---|---|---|---|
| 父级到子级、知识分支 | Tree 树状图 | 知识体系、目录分解、概念分类 | 节点之间主要是时间或因果 |
| 有分支的判断逻辑 | Flowchart 流程图 | 选择、排错、审核、决策 | 只是顺序步骤且没有分支 |
| 按时间发生的事件 | Timeline 时间线 | 历史、版本演进、课程事件链 | 时间不是核心变量 |
| 多角色交接 | Swimlane 泳道图 | 团队协作、职责、跨部门流程 | 只有一个角色 |
| 组件及其连接 | Architecture 系统结构图 | 软件、工具链、平台组成 | 只是在列名词 |
| 输入到处理到输出 | Data flow 数据流图 | 信息加工、AI 工作流、资料沉淀 | 数据并不流动 |
| 状态与转换条件 | State machine 状态机 | 任务状态、生命周期、异常恢复 | 没有明确状态或触发条件 |
| 循环反馈与积累 | Loop 循环图 | 复盘闭环、增长飞轮、学习循环 | 最后一步不会回到前面 |
| 抽象层或能力层 | Layer stack 分层图 | 技术栈、能力栈、从底层到应用 | 层之间没有上下依赖 |
| 两个维度的定位 | Quadrant 象限图 | 优先级、分类定位、策略选择 | 轴无法被清楚定义 |
| 多对象定量比较 | Bar / Line / Radar | 类别、趋势、多指标比较 | 没有可靠数字或统一口径 |
| 集合的交集 | Venn 韦恩图 | 能力交叉、职责重叠 | 交集不是核心结论 |
| 一页高密度总览 | Excalidraw 知识全景图 | 长课程总览、12–18 模块 | 内容短或一种关系已足够 |

## 三、视频笔记默认参数

- 受众：`mixed`，专业名保留英文并补中文解释。
- 尺寸：`doc-wide`，适合 Obsidian 正文横向阅读。
- 细节：`balanced`；节点超过 9 个优先拆为“总览 + 细节”，不要缩成小字。
- 风格：`minimal light`，静态为默认；只有用户明确需要演示顺序时才加动画。
- 输出：每张 `.html`（可编辑源文件）+ `.png`（Obsidian 嵌入）。
- 色彩：只强调 1–2 个焦点；禁用阴影、霓虹、满屏同款圆角框和装饰性箭头。
- 中文：为 CJK 字体提供回退，字号不得小到必须放大才能读。

## 四、生成步骤

1. 从完成后的课堂正文提取“图表候选清单”，每项写出核心关系和读者收益。
2. 删除用三列表格或一段话就能讲清的候选。
3. 每个候选只选一个主导关系和一个图表类型，不混搭多种语法。
4. 绘制前声明：类型、语义模式、尺寸、细节级别、受众、预计删减项；用户已授权直接制作时可继续执行并在交付中记录。
5. 读取 `$diagram-design` 对应的 `references/type-*.md`；涉及行为语义时再读取 `semantic-patterns.md`。
6. 生成自包含 HTML，导出 PNG；每张图只承担一个明确任务。
7. 运行：`python <diagram-design>/scripts/self_check.py <diagram.html>`。
8. 人工检查可读性、连线、中文、焦点、是否比文字更有价值。
9. 在正文相应段落后嵌入 PNG，并链接 HTML；图注标为“AI 生成的内容关系图表”，写明图表类型和用途。

## 五、证据与删减边界

- 图表内容必须来自课程正文、截图、转录或明确标记的外部补充。
- 不得为填满节点而编造组件、步骤、数字、因果或业务名称。
- 任何合并、折叠、删除都写入 fidelity ledger（保真账本：记录源内容有多少、图中保留多少、合并/删掉什么）。
- 原视频截图仍是课程画面的证据；图表、小黑图和全景图都只是解释材料。
- 关键结论旁保留时间戳或截图锚点，不能让美观覆盖事实边界。
