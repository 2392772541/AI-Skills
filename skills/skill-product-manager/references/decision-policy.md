# Skill 决策政策

## 决策顺序

1. 任务是否一次性、低频且没有稳定规则？是则 `NO_SKILL`。
2. 是否已有单个 Skill 覆盖 80% 以上需求？是则 `REUSE`。
3. 是否已有 Skill 覆盖核心流程，仅缺少少量稳定能力？是则 `UPGRADE`。
4. 是否可由两个到四个边界清晰的 Skill 顺序协作？是则 `COMPOSE`。
5. 本机没有能力，但外部已有成熟方案？评审后 `EXTERNAL`。
6. 只有以上均不成立，且任务高频、输入输出明确时，选择 `CREATE`。

## 应当拒绝创建的情况

- 只是保存一段提示词
- 只执行一次
- 输入输出无法描述
- 主要依赖人工审美且没有可验证标准
- 已有 Skill 只需补充一个小规则
- 新 Skill 会复制多个现有 Skill 的全部内容

## 组合 Skill 的边界

组合 Skill 只记录子 Skill 调用顺序、每一步输入输出、失败重试和回滚、中间产物路径以及最终验收标准。不要复制子 Skill 的完整规则。
