# reference-index 母版

## 使用说明

- 这是全片唯一的资产身份台账，产物是一份文件 04-assets/reference-index.md：顶部指针区 + 角色/场景/道具三段，共处一份、统一 schema。"谁是 char-几、密料在哪、声线怎么锁、角度差哪个、这个资产从哪张图长出来的"全看这里。
- 本母版住 script-breakdown/templates/，全库单源；script-breakdown 在索引不存在时按它首建骨架，即结构 + 指针区、条目留空；character-design/scene-design/prop-design 各自只填自己那一段，但都按这套字段，不另定表头。
- 写者规则：当前窗口直写，登记与产出同轮落盘。

## 编号规则

- 角色 char-NNN、场景 scene-NNN、道具 prop-NNN，三位补零，前缀区分类型不混编。编号一旦分配跨集不变。
- 变体加 -vN，如 char-001-v2。新状态 = 新变体，永不覆盖——底图与旧条目原样留档，谱系字段记差异。状态变化如受伤、换装、湿身、损毁，一律走变体，不改原条目。
- 编号由设计站登记时分配，拆解清单只用名字 + 三态占位；分配后全库引用只认编号。
- @编号是项目内部地址，不是平台上传序号。@编号 → @图N 的翻译由 motion-compile 在编译期完成，结果落在 06-motion-prompts/epNN-motion-prompts.md 每条的条头【上传清单】，本索引不管上传顺序。

## 统一字段

每条资产一个块，三段同构；无该字段的类型删行。

- 短串——行内锁身份的一句话浓缩描述。下游提示词里"@编号 + 短串"即可锁定，不重述长相。角色例：38 岁疲惫女维修工，橙白重型工装、左肩编号 M-07。
- 密版——密到五官/材质/陈设级的一整段，只作本台账与设计站出图依据，不进动态提示词成品——i2v 一致性靠 @图绑定 + 短串，长 blob 重描长相会与参考图打架。角色密版按七维公式写；场景密版按材质分区逐段写；道具密版含材质/尺寸/磨损，功能道具另写被操作时的状态时序。
- 声线锁，仅角色——引号内一段逐字复用的声音条件块：年龄口音 + 音区音色 + 语速语气 + 情绪底色及受压变化。凡该角色开口的条，动态提示词的台词行逐字引用本段，连同义词都不换——换措辞就扩大采样范围导致声音漂移。
- 表演档案，仅角色、仅核心角色——一句指针，指向 characters-prompts.md 该角色条目的「表演档案」段；档案本体由 performance 按其母版产出、由 character-design 在角色块预留段位，本索引只记指针不复制正文。边角角色不建档，写「不建档」。
- 出图要求——版式与规格。角色 = 三格法：大特写 3/4 双角度、带笑/不笑两版 + 正面全身去头 + 背面全身，手空、全片不摘的穿戴件照画，中灰底软光，细则在 character-design。场景 = 3/4 视角主图 + 角度覆盖清单，禁正面，细则在 scene-design。道具 = 四视 + 手掌比例参照，细则在 prop-design。
- 角度覆盖，主用于场景、角色/道具按需——两栏对账：已有角度，即这条资产已出的视角清单；需求角度，即 shot-design 镜头表反推的正反打/侧向/出入口/俯仰需求。有缺口就地标注，scene-design 按缺口补产。
- 核心标记——核心/边角，定锁定强度：核心全套锁、边角轻量建档，两档都随资产包一次性出。来源是拆解清单的标记，登记时照搬；下游冒出清单外的核心级新资产 = 拆解遗漏，回拆解补清单再补做。
- 状态——三态 + 集记录：新增记创建集；复用把后续出现集逐个追加，如 新增 ep01；复用 ep03/ep05；变体记原编号 + 差异一句。有它，"改一个资产哪几集受影响、第 N 集要哪些资产"一眼可查。
- 谱系——这条资产的来龙去脉，返工时沿它定位问题层：底图来源——哪张设定图、哪格提取、哪个视频拉帧；关键加工动作——蒙版点改了什么、提取自宫格第几格、局部编辑改过什么；当前生效版本 vN + 旧版本归档位置。原始特写底图永不再整体过模型，变体只做增量编辑——谱系字段就是这条纪律的账本。
- 参考图位置——用户生成后的图落位与文件名约定：char-NNN.png/scene-NNN-角度.png/prop-NNN.png；未生成时写"待生成"。

## 下游取用约定

- shot-design/control-image/motion-compile 一律按"@编号 + 短串"引用资产；密版不出台账。@绑定句式——唯一职责 + 反向排除、场景"只控几何材质光线氛围不控构图"——归 motion-compile 的 asset-binding 规则，本索引只管身份数据。
- 图像提示词规则——无负面参数、纯正向——归三个设计站各自声明；视频提示词规则归 motion-compile。两套规则集隔离，本索引不承载任何一套。
- 同步即时：任何资产一变，先更本索引再动下游；索引落后于实际产物，下游就会 @ 到错的或不存在的资产。多集复用不重做设计、不重出图，但必须把本集追进状态行的出现集——这是登记动作，不是可选项。
- 资产审与成片审拿本索引对账两类问题：死引用，即提示词里 @ 了索引查无的编号；身份漂移，即短串与密版不符、变体没走谱系。
