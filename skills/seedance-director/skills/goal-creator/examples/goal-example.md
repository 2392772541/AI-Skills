# 标杆 · 连夜自驱做完 EP01 的 /goal 指令

## 示例定位

场景设定，自洽示例：单集短片《当票》项目。进度：★适配确认、★拷问确认与 EP01 的 ★拆解 / ★资产 / ★表确认均已过，decisions.md 有记录；8 场中场 1–2 已完成编译与台账。用户睡前说："剩下的你连夜跑完，明早我来验收交付。"——典型的型 2 至集完成：编译段 + 成片审 + 交付即提示词包，止步成片审通过 前。

下面先给成品指令，即用户复制发送的整段，再逐段注解为什么这么编。

## 成品指令

```
/goal 完成 EP01《当票》场 3–8 剩余编译段场次并通过成片审，交付即提示词包，止步验收前。

预授权范围：
- 已过：★适配确认、★拷问确认、EP01 的 ★拆解确认 / ★资产确认 / ★表确认，00-bible/decisions.md 均有记录。
- 终点线：推进至成片审通过、验收前——06 提示词包与头部「生成顺序与校准」小节备齐、验收材料备好即停：提示词包摘要 + 全文指针 + 「现在去生成 vs 再修一轮」的正反最强案 + 一个问题，等我验收。
- 表确认全部跳过，即批量连跑；连跑中冒出核心级新资产回拆解补清单并补做，事后汇报。

完成的标准：
1. 场 3–8 每场：03-shots/ep01-shots.md 本场镜头表，含场阐述、逐镜六字段、导演意图、结束状态五字段、控制等级、衔接；05-control-prompts/ep01-sXX-control.md，按控制等级需要的场；06-motion-prompts/ep01-motion-prompts.md 本场逐条九段成品。
2. 结构硬指标：恒定层与 00-bible/visual-style.md 逐字一致、结束状态五字段逐条齐、@ 引用零死链、条头清单与正文双向对账且连号——逐项动手核并贴证据。
3. 成片审：.review/final-ep01.md 在且结论 PASS，含跨场结束状态继承链逐缝核对。
4. 报告时效：该报告须晚于所审产物的最后修改——产物后来又改了，旧报告作废，重审后才算数。
5. 07-continuity/ledger.md：场 3–8 逐场落幅入账，跨集 ending state 区已更新。
6. 06 头部「生成顺序与校准」小节在——验证环序 / 图像生成顺序 / 条生成顺序 / 校准自查四项 ≤10 行；★交付确认材料备好即停：提示词包摘要 + 抽验指引 + 遗留风险。

验证方式：
- 产出物清单按场打勾，含表+控制图+条数；贴成片审报告的总判定与问题计数；收尾给一行进度。

约束：
- 不覆盖已定稿的场 1–2 任何产物及其审核报告。
- 条 4–30s，待实测；单条主体 ≤5；台词与镜头表逐字一致。

停点：任一级审核熔断——连续两轮 FAIL 或判据分歧 → 停，摆证据与分歧待我裁决；提示词包即交付 → 停在成片审通过 前。

执行策略：目标导向，一条路不通换方法——改措辞、重选轨、回上游环节修源头，穷尽才停；预授权范围内全程自主不中途确认；每场完成记一句进度。
```

交付时附一句：复制这段发送即可启动。指令止步在成片审通过 验收前，明早你看到的应该是备好的提示词包和验收摘要；场 1–2 我不会碰。

## 全例总注

### 目标行

为什么这么编：

写"场 3–8 + 成片审 + 交付即提示词包至成片审通过 前"而不是"做完 EP01"——区间左端排除已完成的场 1–2，配合约束里的不覆盖；右端点名终点线。目标行是 evaluator 理解范围的第一依据，模糊的"做完"会让自驱把重做场 1–2 也当成分内事。

### 预授权范围

为什么这么编：

- "已过"两行是起点凭证：写明 decisions.md 有记录，自驱启动时按 [项目状态检测与路由] 扫描就能核到，不会误判"表确认 未过"而卡在起点。
- "终点线"把成片审通过 显式立为停止条件并写清停下时要备好什么——确认材料按确认呈现协议备料，交付这一关的真分叉就是「现在去生成 vs 再修一轮」，摆正反最强案再只问一个问题，不拿表确认那套摘要糊过去。不写这行，自驱循环会把"交付完成"理解成连验收一起判掉，等于替用户点了头。
- 本例没有显式预授权段：用户没有拍板任何未过的确认点，所以一个都不起草。什么时候才写：比如用户说"大纲不用等我看了，按现稿定"，才写"表确认 按大纲 v1 现稿视为通过，启动即记入 decisions.md"，并在交付时单独提醒这句话的分量。
- 表确认跳过一行对应批量连跑开关的语义；"核心级新资产回拆解补清单并补做，事后汇报。

### 完成的标准

为什么这么编：

- 第 1 条按编译段产物链写实名路径，即表 → 控制图 → 条，evaluator 拿清单能逐项对存在性；"按控制等级需要的场"一句留了合法弹性——不是每场都有控制图，写死"每场必有"反而制造假失败。
- 第 2 条只写可数可 diff 的机械硬指标——恒定层逐字、五字段齐、@ 零死链、清单连号，逐项动手核并贴证据。挑"节奏好""有电影感"这类不可自证的写进来只会稀释判定。
- 第 3、4 条是门禁本体：成片审写实名报告路径，第 4 条管时效——场 3–8 若在审后又被改动，旧报告即失效，得重审才算数。门禁不写，等于没审——这两行是全母版唯一不许删的。
- 第 5 条把台账写进完成标准：台账步是编译段里的必经步骤，不写这条，自驱最容易漏的就是它——不产新提示词、看起来"不影响交付"，但漏了下一集开场就断链。
- 第 6 条对应型 2 目标的交付段，落到 06 提示词包齐备、头部小节四项与抽三条回验条头清单这种可点验的形态。

### 验证方式

为什么这么编：

全部是"能在输出里自证"的动作：打勾清单、贴报告总判定、一行进度。没有让 evaluator 去"评估质量"的动词。

### 约束

为什么这么编：

只有四行，每行都是真硬指标：第一行保护已定稿产物，这是不可逆风险最高的一条；后三行是本项目当前最容易被自驱压力挤破的边界。没有"保持高质量"式空话。

### 停点与执行策略

为什么这么编：

停点两句对应两个保险丝：审核熔断即停防死循环——连续两轮 FAIL 或判据分歧即停，终点线防越权。执行策略用通用一行话术，不展开——展开的每一个字都在挤占 4000 字符里完成标准的空间。

### 字数

为什么这么编：

成品指令约 1500 字符，余量充足。若目标涉及多集或场数更多导致超限：先删执行策略展开与验证方式细目，再合并约束行；完成标准与门禁即第 3、4 条加门禁时效一句一个字不删——宁可目标拆成两条 /goal，也不删门禁。
