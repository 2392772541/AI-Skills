# Skill 候选评分表

评分目标不是判断“内容多不多”，而是判断它能否稳定驱动 Agent 完成真实工作并留下可核验证据。总分 100。

| 维度 | 权重 | 判断方法 |
|---|---:|---|
| 真实工作流匹配度 | 18 | 是否覆盖用户真实输入、关键决策、步骤和输出，而非泛化口号 |
| 与本机能力互补度 | 10 | 分数越高表示重复越少；能复用或组合时不应复制一套近似能力 |
| 发现契约与适用边界 | 12 | description 是否同时说明 what/when；正文是否有正向触发、负向排除和相邻 Skill 分工 |
| 工作流强制度 | 15 | 是否有明确顺序、门禁、停止条件、失败处理；关键步骤能否被脚本或检查项约束 |
| 证据化完成标准 | 12 | “完成”是否要求测试输出、构建结果、截图、diff、哈希、统计等可复核证据 |
| Eval 覆盖 | 12 | 是否有结构校验、路由正向、路由负向、典型行为和压力/失败场景 |
| 安全与维护成本 | 10 | 权限、网络、密钥、二进制、依赖、平台和更新频率是否可控 |
| 可移植与自包含 | 6 | 单独安装后链接、脚本和 references 是否仍可用；跨 Codex/Claude/Cursor 时是否降级清楚 |
| 来源与许可证 | 5 | 来源是否可信、版本是否可追踪、许可证是否允许使用和修改 |

## 强制门槛

即使总分较高，出现以下任一项也不能直接晋级：

- 正式 Skill 会被同名覆盖，且没有 diff、备份和回滚方案。
- description 没有明确触发条件，或使用“处理任何任务”等过宽表述。
- 有脚本/网络/写操作，却没有权限边界和失败处理。
- 只写“确保质量”“充分测试”，没有可执行命令或可观察证据。
- 外部 references 使用仓库级相对路径，单独安装后会断链，却没有复制或适配方案。
- 没有至少一个负向路由样例，无法证明不会抢占相邻 Skill。

## 评分结论

- `85-100`：可进入晋级评审；仍需通过全部强制门槛和测试。
- `70-84`：进入 `needs-review`，补齐门禁或 eval 后再评审。
- `50-69`：只保留为研究候选，不建议激活。
- `<50`：不引入；提取局部设计方法即可。
