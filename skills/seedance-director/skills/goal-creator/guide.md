name: goal-creator
description: 当用户想把一段流程目标交给 /goal 自驱执行，说"自动跑完/批量做完/连夜自驱/帮我写个 goal"时使用。结合项目状态编译一条带预授权范围、四个审核点与逐站确认处置、可自证完成条件的 /goal 指令，交用户复制发送启动。产出可直接发送的 /goal 指令文本。

[任务]
    结合当前项目状态与对话，理解用户接下来要自驱完成什么，按 [Goal 模板] 编译一条 /goal 指令，放进代码块交用户复制发送。
    本 skill 只准备指令，不替用户触发——slash command 必须用户自己发。
    /goal 自驱 = 预授权范围内全程自主：各确认点按预授权处理，等效批量连跑；工程细节自决；拆解审 / 资产审 / 镜头表审 / 成片审照常派 film-reviewer 审。但确认点是用户的权力，指令必须把预授权范围写死——自驱从哪起、推进到哪、在哪停。

[依赖检测]
    无前置产物门槛。

[第一性原则]
    本环节是【导演思维】第 5 问「下一步」的展开：把"接下来一大段该做的事"编译成一条自驱指令——范围、终点、门禁、停点全部显式，发出去就不需要用户在场。
    上下文感知：从项目进度、decisions.md、用户刚说的话推断目标，不让用户从零写。一句话能说清的目标别让用户写一段。
    确认点不可绕：适配 / 拷问 / 拆解 / 资产 / 表 / 交付各确认永不跳，/goal 不能替用户点头。指令里每个涉及的确认点必须落进三种合法形态之一：已过，即 decisions.md 有确认记录，写进预授权范围作为起点凭证；终点线，即自驱推进到该确认点前，材料备齐即停——正式确认不是过目，材料按确认呈现协议备：摘要 + 全文指针 + 挑一到两个放大系数最大的未决分叉摆正反最强案 + 最后只问一个问题；显式预授权，即用户亲笔在指令里写明"某确认点按某拍板视为通过，启动即记入 decisions.md"——可以起草这一段，但交付时必须单独点名提醒它的含义，让用户知道自己在授什么权。未写预授权声明的确认点一律按终点线处理。
    审核写进完成条件：四个审核点，即产物 + 对应报告结论 PASS，按区间逐个显式写进完成标准——含拆解写拆解审、含资产写资产审、含镜头表写镜头表审、含集成写成片审，一律实名路径。门禁不写等于没审，自驱循环会绕过它直接判完成。报告还有时效：产物晚于报告即作废，重审后才算——判读写成「报告不早于对应产物最后修改」，否则自驱拿着旧报告判完成。审核保险丝进停点：熔断即停——同一审核点连续两轮 FAIL、或对判据有分歧，摆证据待裁决，不自转第三轮。
    完成条件可自证：/goal 的 evaluator 只判已 surfaced 的内容——完成标准写成能在输出里自证的形式：列产出物清单逐场打勾、贴各级报告总判定与问题计数、收尾给一行进度。"提示词质量好"不可自证；"每条九段齐全、恒定层与 visual-style.md 逐字一致"可自证。对账类硬指标写成可数可 diff 的一句，如「恒定层逐字一致、@ 零死链、清单正文连号」，省下的字符全留给语义标准。
    边界要硬：约束只写真实硬指标——不覆盖已定稿的场/条、条 4–30s 且数值待实测、单条主体 ≤5、恒定层逐字——同类项并成一句，不逐条罗列。不写"保持画面质量"这种放之四海的空话。
    字数硬限：/goal 有 4000 字符上限，超了发不出去。每个字带信息——删套话、删排版装饰；压不下时先删执行策略展开、再合并约束，完成标准与门禁一个字不删。
    不填形式：完成标准是唯一必填核心；预授权范围在目标涉确认点时必填；验证、约束、停点、执行策略只在真带信息时写。简单目标就目标 + 完成标准 + 门禁三段。
    目标必达：执行策略写成目标导向，一条路不通换方法——改措辞、重选轨、回上游环节修源头，同一难点穷尽多法仍不达标才停，不一卡就停。
    平台事实核实：指令里涉及的路径、审级、字段名以本库 canonical 为准，即 CLAUDE.md [文件结构] 的结构表；拿不准的当场查文件，不臆写。

[Goal 模板]

    /goal 完成 {{目标一句话，含集/场区间，如"EP01 全部 8 场的编译段并通过成片审"}}。

    预授权范围：

    - 终点线：推进至 {{成片审}} 通过即停——交付即提示词包，无需另备交付材料。
    - 〔仅用户明确拍板时写——显式预授权：{{适配确认/表确认}} 按 {{拍板内容}} 视为通过，启动即记入 decisions.md。〕

    2. {{结构硬指标：每条结束状态五字段齐、恒定层与 00-bible/visual-style.md 逐字一致、@ 零死引用}}

    验证方式：
    - 列产出物清单逐场打勾；贴各级报告的总判定与问题计数；收尾给一行进度。

    约束：
    - {{真硬指标才写：不覆盖已定稿的场 1–3 / 条 4–30s、待实测 / B 轨不写秒数 / 单条主体 ≤5}}

    停点：任一级审核熔断——连续两轮 FAIL 或对判据有分歧 → 停，摆证据与分歧待我裁决；到达终点线确认点 → 停，备好「摘要 + 全文指针 + 一到两个未决分叉的正反最强案 + 一个问题」。

    执行策略：目标导向，一条路不通换方法——改措辞、重选轨、回上游环节修源头，穷尽才停；预授权范围内全程自主不中途确认；每场完成记一句进度。

[认目标]
    从项目进度与用户话语确定自驱区间。常见四型：
        - 整集自驱 · 型 1——表确认已过：全部编译段场次，止步成片审前或含成片审；
        - 至集完成 · 型 2——编译段逐场走完 + 成片审，成片审 PASS 即集完成，提示词包备好即停；
        - 指定几场 · 型 3——重做/补做指定几场的编译与台账，随后重跑成片审；
        - 下一集前段 · 型 4——多集串行连产：本集适配 → 拆解 → 资产包 → 全集镜头表，四审照派，止步 ★表确认前，其余确认按预授权处理。
        - 吃不准区间就问一句，别猜。

[查凭证]
        - 读 decisions.md 确认哪些确认点已记录；目标区间越过未确认的点 → 默认把该点改写为终点线；用户明确说了拍板内容才起草显式预授权段。

[填母版]
        - 完成标准逐条可自证；门禁按区间涉及的审级写实名报告路径，并带上报告时效那一句；约束从本项目实际取，有已定稿场就写"不覆盖场 1–3"；台账更新写进完成标准——台账步是编排里的必经步骤，自驱不许漏；整条压进 4000 字符。

[交付]
        - 整条 /goal 放代码块 + 一句"复制发送即可启动"；有显式预授权段的单独点名提醒；涉及覆盖已有产物的提醒发送前扫一眼约束。

[不替用户发送]
        - 不自己启动任何自驱。
