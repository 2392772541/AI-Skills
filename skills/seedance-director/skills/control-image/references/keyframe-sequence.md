[定位]
    用 N 张按时间顺序排列的图，把一条视频里"必须长成特定样子的时刻"逐个钉死。模型在关键帧之间自行补全运动；帧管构图与到位时刻，运动由动态提示词的文字驱动。
    本卡管三件事：帧从哪来的帧源、帧怎么排的顺序纪律、帧怎么绑的绑定句式与防复制声明。

[帧源]
    每一帧落笔前先回答"这帧从哪来"，四个来源按优先级排：
        1. 真帧，最高优先，且是生成期回填项：kf1 = 上一条 c(N-1) 成片的尾帧截图。身份、光线、调色零漂移，是条间承接的第一选择。但本站开工时全集还没生成过一帧——c(N-1) 的成片物理上不存在，**本站不产这一帧的生成提示词**，只做三件事：发编号、写承接绑定句、写清截帧要求。截帧要求写全三条：从 c(N-1) 成片截尾帧、选运动模糊最小的一帧、对照 07-continuity/ledger.md 的上条落幅五字段——位置、朝向、持物、动作动势、情绪——核对画面内容一致。产出卡「帧源与谱系」写「生成期回填 · 需先完成 c(N-1) 并截尾帧」，「生成提示词」栏填「——」；交接清单给 06 头部「生成顺序与校准」小节标该条前置，让顺序里 c(N-1) 排在前面。
        2. 已有资产图：场景角度图、角色全身图等已登记资产可直接充当关键帧，常见于定场镜头首帧 = 场景 3/4 角度图。直接引用资产编号，不新生成。
        3. 宫格提取帧：需要新构图、或一批帧要锁同脸同景同调时，走 grid-method.md 生产底板并逐格提取，提取物登记为 ctrl-epNN-sXX-cN-kfX-vN。
        4. 单帧直出：只缺一帧且构图明确时，写单帧生成提示词直出。提示词结构：从 00-bible/visual-style.md 逐字嵌入的通用基准段 + 本场景所属场域那一句场域锚句——单帧直出是带画面内容的整帧场景图，与场景板同源同字，少了锚句这一帧就不带年代物证、与它要校色的场景板对不上 + 按资产编号的场景与人物引用 + 构图与景别描述 + 光线方向。遵守图像侧规则：正向描述，不写负面参数——图像提示词规则集由资产类 skill 声明持有，此处同规则。
    第 1 项与第 2–4 项的分界是本卡最容易走错的一道：第 1 项交的是一条生成期指令，第 2–4 项交的是本站现在就能写完的提示词或引用。别为了让本文件"看起来齐"，给承接帧补写一条生成提示词——那等于放着零漂移的真帧不用，凭空造一次身份与调色漂移。
    帧数纪律：N=1–5 张/条，待实测校准。每帧对应镜头表里一个明确的画面节点；没有节点对应的帧删掉——多一帧就多一分帧间漂移与参考位占用。

[顺序纪律]
    - 上传顺序 = 时间顺序 = 编号顺序。关键帧在条头上传清单里必须连续相邻排列，不与其他资产图穿插——motion-compile 排该清单时落实，本卡把它写进随块的附加顺序注记：那是上传动作，不写进生成框对模型说。
    - 绑定块与正文归属句一律用 ctrl 编号 ctrl-epNN-sXX-cN-kf1–kfN 指代，不带版本后缀、不写死 @图N；由 motion-compile 编译该条时统一翻译成 @图N、并登记进条头上传清单。角色与场景在块内不写编号、只写代称——它们各有自己的绑定条目。
    - 同场全部关键帧投喂 i2v 前必须过同场调色校准：选本场最贴近场景设定图的基准帧，其余帧全部校到同一基准，不是各自单张最好看。颜色误差会两级累积——设定图 → 帧变一次色、帧 → 视频再变一次——且生成图不是高宽容度原片，后期拉不回来。本站在产出卡「调色状态」字段登记：未校/已校-基准帧编号。执行关卡在 06 头部小节的校准自查。

[绑定句式 · 一次在块、二次在正文]
    关键帧是全库唯一有二次点名权的类型，位置是硬规则：绑定块内只写一次总声明，逐帧归属落到正文它管辖的那一段或那一镜里再点一次名。把整串帧连同各自时间点堆进绑定块，是把「一次绑定」写成三到六次重复，模型直接拒绝启动。本节是只读副本，真相源在 motion-compile 的 asset-binding.md [控制图绑定]。下文的 @……-kfK 是 SKILL.md [编号与版本 · ctrl 真相源] 那串完整 ctrl 编号的省写。
    块内那一句：总声明 + 防复制双列表合成一句，块内不再出现第二个帧地址，也不 @ 角色与场景——它们各有自己的绑定条目，指回去一律用代称：
        以 @……-kf1 至 @……-kfN 的顺序作为本条关键帧，画面按此顺序依次到达各帧所示内容，顺序 = 时间顺序；这一串帧作为【构图与时刻】唯一参考：允许借用其构图、景别、人物位置、光线方向与到位时刻；不得复制其静止性——帧与帧之间的全部运动由本条文字驱动，画面不在任何一帧处停顿或跳切。人物面孔、体型、服装以角色参考为准，场景材质与光线氛围以场景参考为准；帧与角色参考冲突时，以角色参考为准。
    正文那一次：逐帧归属按轨型选写法，随块外注记交 motion-compile 落进对应位置。单帧条且这一帧就是首帧时，首帧锁并进块内那一句、正文不再点名——一个编号一次，够用——
        首帧锁：视频从 @……-kf1 所示画面开始，首帧即该帧的构图、景别与人物位置。
        A 轨中途帧，写在它管辖的那一段段内，秒级 [X.X-Y.Ys]，帧级写法亦可：本段构图与站位以 @……-kfK 为准，镜头运动至该构图后{{写清运动方式}}。时间戳对到位时刻的遵循度标注：待实测校准。
        B 轨，写在对应镜头行内，不写秒数：本镜构图以 @……-kfK 为准——景别、机位、人物位置与该帧一致。
        尾帧锁，需要落幅精确时：视频在 @……-kfN 所示画面结束，落幅构图与该帧一致，动作停在{{写结束状态动势}}。
        条间承接特例，真帧承接——绑定句本站现在就写全，图由用户在生成期截出后按此编号上传：@……-kf1 为上一条视频的最后一帧画面，本条从这一画面无缝继续，人物位置、朝向、持物、光线与之完全一致，动作从{{上条落幅动势}}继续，不重新开始。
    一帧管多镜时，正文里每个受管镜头行各点一次名，都落在它管辖的镜内，合法——铁律数的是绑定块内的出现次数，正文的归属点名不计入；绑定块内仍只有那一句总声明。
    帧间一致性由生产侧保证——同源宫格、同一基准调色——不靠视频侧文字找补。
    首尾帧模式，平台界面的双帧特例：
        只有首帧 + 尾帧两个锚点、中间运动完全交给模型时，改用平台「首尾帧」模式而非全能参考：首帧图 + 尾帧图 + 一句运动描述。适合开门进屋、转身离开这类单动作过渡条。选型注记写明用了此模式，06 头部生成顺序小节照记。

[判据卡 · 该用关键帧序列]
    怎么认：
        条内存在 1–5 个"必须到位"的画面节点——首帧构图、中途某个构图性时刻、落幅——且节点画面能用一张静态图完整表达。对话正反打的每个机位位、定场镜头的开场构图、条间接缝，都是典型节点。
    认错长什么样：
        - 帧数≠节点数：给 10 秒条塞 5 帧"保险"——帧间漂移与预算爆炸，反而更抖。
        - 用帧管运动：两帧之间隔着复杂动作链，指望模型"从A帧变到B帧"自己想出过程——运动必须由文字逐拍写出，帧只管两端。写不清过程的条该升级类型 4 白模。
        - 帧源混杂：kf1 来自宫格、kf2 单帧直出、kf3 从旧图改——三帧三种脸。同条帧尽量同源；不同源时必须同过一次调色基准并肉眼比对身份。
        - 静帧复制：成片在关键帧时刻明显停顿一拍，模型把帧理解成了"要展示的图"——绑定块缺防复制声明，补「不得复制其静止性」句。
        - 绑定块里逐帧堆地址：kf1–kf5 连同各自时间点全写进块内，一条绑定写成五次重复，模型拒绝启动；块内只留总声明，归属落正文。
        - 用生成帧做承接：明知 kf1 该是上条成片的真尾帧，却因为"本站要交一条生成提示词"而生成一张"接近落幅"的图顶上——放着零漂移的真帧不用，凭空引入身份与调色的双重漂移。承接帧就该是空的生成条 + 一条生成期回填指令。
    典型例子：
        - 对话条，B 轨 6 镜正反打：3 帧 = 主机位双人位/正打/反打，块内一句总声明，每镜在正文镜头行内点名「本镜构图以 @……-kfX 为准」，同一机位复用同一帧。
        - 长镜条，A 轨 22 秒：3 帧 = 起幅全景/12 秒处中景到位/落幅特写，时间戳绑定各帧。
        - 承接条：kf1 = 生成期从上条成片截的尾帧，本站只发编号 + 总声明 + 承接特例句式 + 截帧要求，其余交文字；kf2 起若另有节点，照常在本站写生成提示词。
