description: 当用户带着剧本、小说、章节体长文本或任何故事文字进入项目，说"用这个拍片""改编这个小说""这个故事能不能拍"，或剧本落盘后发生任何改动、需要按版本增量重跑三类改造扫描并传播下游时使用。判定输入类型并路由：完整剧本与小说执行结构改造、可视化改造、可实现性改造三类改造；梗概与想法转 director-grill 定蓝图后由 script-write 共创。产出改造版剧本 01-script/epNN.md，头部附改造清单，随适配确认 一并呈现。

[任务]
    剧本适配，整条流水线的进料口。职责三件：
        - 判定用户输入属于哪一类——完整剧本、小说与长文本、梗概与想法——按路由表分流；
        - 对剧本与小说执行三类改造——结构改造、可视化改造、可实现性改造——把「给读者的文字」改造成「给摄影机的文字」；
        - 产出改造版剧本 01-script/epNN.md 与改造清单；剧本落盘后的任何改动由本站执行版本传播：圈增量 → 对增量重跑三类扫描 → 记版本区 → 列下游影响清单提醒。
    进站两次：收稿——只做输入判定与原样存档、不改稿，交 director-grill 对着原稿拷问；收口——拷问裁决在手后按蓝图与裁决做三类改造，一次改完。上游：用户本人，本站没有更上游的站；收口的依据来自 director-grill 的蓝图与裁决清单。下游：剧本拆解 script-breakdown。确认时点见 [落盘与移交]——首集随立项收口交 ★适配确认，改造清单是随呈材料。
    多集项目中，全季与全片层面的适配（集边界切分、season 弧）在立项收口对照 series-outline 做；分集剧本的本集细调随该集开工进行。

[依赖检测]
    必需，缺了挡：
        - 用户提供的故事文本。剧本/小说/梗概/大纲皆可，任意形态、任意载体：粘贴文本、.md/.txt/.docx/.pdf 文件。
        - 缺 → 挡：本站上游就是用户，请用户先给出故事材料；一个字都没有、只有"想拍个片"的冲动 → 直接转 director-grill 从零访谈，随后 script-write 共创。
    必需，有活干：
        - 先做输入判定路由，见 [输入判定路由]，再决定走改造还是转站。
    分步而异，收稿与收口各查各的：
        - 收稿步：只需用户输入，判定 + 存档即完成、不动笔，无其他依赖。
        - 首集收口步：必需 00-bible/creative-brief.md 与 decisions.md 的拷问裁决清单——蓝图与裁决是三类改造的依据，缺 → 挡，先回 director-grill 拷问；多集另对照 series-outline.md 定集边界，缺 → 切分取舍挂待决区。
        - ep02 起的本集适配与再入：蓝图已定稿在盘，直接对照做；改造中的创作取舍留「待决」挂进改造清单，到 ★适配确认 一并裁决。

[第一性原则]
    本环节是【导演思维】第 2 问「画面化」的展开：把不属于摄影机的文字改造成能被拍出来的文字——每一句都要能回答「画面里具体看见什么」。
    剧本是给摄影机的：不是给读者的。小说可以写"他想起十年前"，摄影机拍不到「想起」；改造的全部工作 = 把心理、概括、氛围翻译成动作、表情、环境变化、物件细节。
    两步偷懒是万恶之源："直接把小说丢给 AI 拆分镜、复制描述就跑图" = 后面越做越乱。真实剧组导演开拍前一部剧本要看十几遍——本站就是那十几遍里的第一遍。
    蓝图先于改笔：三类改造处处是创作选择——独白翻成什么可见行为、雷区场走哪条改造路线——依据全在蓝图与裁决里；所以首集改笔落在拷问之后的收口，一次改完、不写两遍。
    可实现性前置：当前模型跑不稳的画面——复杂群体动作、连续物理交互、精确口型、画面内文字等——在剧本阶段删改，远比中后期发现跑不出来便宜。但删改属创作取舍 → 问用户，待决项挂适配确认，本站不擅自砍戏。
    可回溯资产链：剧本是链条最上游——本站对版本传播负全责。改剧本是主流程常规动作、不是意外：剧作审计加戏、★适配确认裁决回写、下游发现剧本事实有误，都会回头动剧本；而后加的段落最像剧本、也最没被查过——一次三类改造都没过过，所以版本增量必扫；扫完还要提醒下游，分镜、设定文本、设定图都可能需要联动更新。

[输入判定路由]
    判定依据按序检查，看形状不看文笔：
        - 有场次结构——场头或等价分段——加成型台词，且情节完整 → 完整剧本 → 只做后两类改造，结构改造只做查漏：补场头缺项、拆跨时空的场。
        - 章节体或无场头的连续叙事文，如小说、故事文、口述整理稿 → 小说与长文本 → 三类改造全做。
        - 只有故事梗概、点子、beat 列表、人物设定，没有场次没有台词 → 梗概与想法 → 转站：先 director-grill 访谈层定蓝图要素——片种、风格、story goal、叙事范围——再 script-write 共创写作；写完由 director-grill 对成稿补跑剧作审计（裁决记账），本站在收口只做可实现性改造并并入裁决——可视化已在写作中内建。
        - 边缘输入：部分场次成型的半成品剧本 → 成型部分走改造，缺口场次转 script-write CO-WRITE 补全后合流；分镜脚本与镜头列表 → 说明本流程以剧本为源头真相，先协助逆向整理成场次化剧本再进流程。
        - 判定完成即把原始输入原样存入 01-script/source/；收稿到此为止——三类改造留到收口，拷问蓝图与裁决在手才动笔。

[三类改造]
    完整剧本做后两类，小说与长文本三类全做；逐类细则住 references/three-transforms.md，雷区表住 references/feasibility-checklist.md：
    - 结构改造：章 → 场按「同一时空的连续动作」切，场头补全内外景 + 地点 + 时段、时间地点歧义清零；多集按 series-outline 切或产切分草案；叙述视角一律转摄影机外视角——叙述者知道的 ≠ 画面看得见的。
    - 可视化改造：逐场逐段问「这一句，画面里具体看见什么？」回答不出就按四条转写路径改写；超长独白标记拆短或加反应节拍。
    - 可实现性改造：全文雷区扫描，命中按处置顺位——等效改写 → 降档 → 标注放行 → 删（挂待决区，适配确认 裁决）；处置前对照 [绿档误杀清单] 防过度阉割。

[衔接与歧义终检]
    场间可接——前场结尾的动作、视线、空间关系后场能承接；场内可拍——抽查任意段落问「画面里具体看见什么」；时间地点歧义清零；人物首次出场带年龄外貌括注。

[落盘与移交]
    改造版写 01-script/epNN.md，头部集信息块 + 改造清单（待决区 + 版本区）照 script-write 的 screenplay-format-template.md；重大删改理由补记 decisions.md。确认时点分两种：首集在立项收口——拷问结束后按蓝图与裁决清单做三类改造、一次改完落盘（多集先对照 series-outline 定集边界，切分结果回写其集结构表的场次范围列），向用户报总摘要——改了几处、待决几项、全文指针——交 ★适配确认定终稿；ep02 起随该集开工做，改完当场交 ★适配确认。确认过后剧本冻结、单向下传，动它只走 [再入协议]。

[再入协议 · 事件驱动]
    01-script/epNN.md 动了一个字就是一次版本增量，不论出自谁手：本站自改、剧作审计加减戏、★适配确认裁决回写、确认引发的人物或道具改动、下游站发现剧本事实有误——一律回本站走本步，别站只提改法、不落笔改剧本正文；收到指向本站的 FAIL 派活同样走本步。
        - 增量重扫铁律，绝对不能少：先圈增量——本次新增、改写、删除的段落逐段圈出来，这就是扫描范围；再对增量重跑三类改造扫描，一类不许跳——结构查新增段有没有跨时空要切场、场头三要素齐不齐、场号要不要重排；可视化对增量每句问一遍「画面里具体看见什么」；可实现性拿增量对 references/feasibility-checklist.md 逐卡过一遍，「看着没雷」不算扫过。只扫增量、不重扫全本，成本才付得起。
        - 范围外扩，四类改动触发：改了跨场承接物或道具状态、改了人物固定特征、增删场次或调顺序、改了场结尾落幅——把依赖它的上下游场次一并扫进来，断链只在缝上显形。
        - 回填与记账：新命中以行内【生成注记】留痕、带卡号尾标，新出的删改挂待决区；版本区新增一行，写明本次增量范围 + 三类扫描各自结论 + 下游影响提醒——扫过而无命中也要写「三类扫描已过、无新增处置」，不写等于没扫；只动记账数字、正文一字未改的改动走轻档，版本区照记并注明「正文未动、免扫」。
        - 下游影响对照表，按表列出受影响文件清单，只提醒不自动改，遵迭代即同步原则：
            - 台词改动 → 02-breakdown/epNN-breakdown.md、06-motion-prompts/epNN-motion-prompts.md 的声音四要素段
            - 动作与调度改动 → 02-breakdown/epNN-breakdown.md、03-shots/epNN-shots.md、05-control-prompts/、06-motion-prompts/
            - 场次增删与顺序调整 → 02-breakdown/ 起全链 + 07-continuity/ledger.md
            - 人物、场景、道具增删 → 04-assets/reference-index.md 及对应 prompts 文件 + 上述全部
            - 场结尾落幅改动 → 07-continuity/ledger.md——条间与跨集承接

[完成标准]
    确定性自检动手做：本站产物里可数、可对照的项逐一核过，不凭「看起来对」；查出的当场修，修完才交。
    1. 原始输入已原样存档 01-script/source/，改造版已落盘 01-script/epNN.md，两者可逐段对照回溯。
    2. 每场有合规场头，内外景、地点、时段三要素齐全，全本时间地点歧义为零。
    3. 正文任取一段能回答「画面里具体看见什么」；不存在「想起、感到、意识到」类不可拍叙述残留，已显式改写为画面的闪回除外。
    4. 可实现性扫描覆盖全文，每处命中的处置以行内【生成注记】留痕、带「——卡 NN 处置」尾标；删改类无一例外挂待决区，没有擅自删除的剧情承重画面。
    5. 改造清单两块齐全——待决区、版本区；处置本体全在正文行内注记，头部不复述；多集切分已回写 series-outline 场次范围列。
    6. 剧本改动再入时：本次增量范围已圈定、三类改造扫描已对增量逐类跑过并写下结论，版本区已更新——头尾版本号动手核一致，下游影响清单已列出并提醒。

[禁止]
    - 禁止把小说或梗概原文直接放行给 script-breakdown——两步偷懒是万恶之源。
    - 禁止未经用户点头删除剧情承重画面——删改是创作取舍，一律走待决区。
    - 禁止把可实现性改造做成过度阉割：命中 [绿档误杀清单] 的画面不许删——长场可拆条、夜戏可布光、情绪重头戏可物理化。
    - 禁止输出无场头的场、带时间地点歧义的场头。
    - 禁止剧本正文改了却不走再入协议——增量不重扫、版本区不更新、下游影响清单不列，缺任一项都是版本传播断链；别站发现剧本该改，回本站改，不许自己落笔改剧本正文。
    - 禁止在剧本里写镜号、景别、运镜、提示词参数——那是 shot-design 与 motion-compile 的事；剧本只管故事与画面。
    - 禁止替 director-grill 做蓝图访谈、替 script-write 写全新场次——判定为梗概与想法就转站，不越站代工。
