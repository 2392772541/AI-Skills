[定位]
    三格法是本站出图版式的默认与唯一主版式，经长片量产实证——600 个已批准资产、137 场全程可辨认。核心思路：一张图三格 = 同一次噪声 = 同一个人；再配两个关键 hack——全身格去头、特写笑/不笑两版——把「脸的来源」收敛到唯一一格。角色出图不再走四视白底版式，一律以本法为准。
    本卡每节按「怎么认 / 认错长什么样 / 典型例子」给判据。

[三格构成]
    怎么认：
        一张图、三格水平排列——
            - 大特写：三四分之三视角，一个角度同时给出正、侧两面的信息；头肩构图，默认不笑版，嘴唇自然闭合；
            - 正面全身 · 去头：画面从领口/颈部以下取景，交代身形、服装剪裁、鞋，不含头部；
            - 背面全身：完整背面含后脑发型，交代背部剪裁、发型背面与垂坠。
    正文双保险：
        开头写一遍版式，正文再复述一遍「三格必须是同一个人，发型发色、服装、体型完全一致」——即 "the same person, consistent across all panels."（同一人，跨格一致。）只写一遍，模型会把三格画成三个人。
    手空与穿戴两分：
        双臂自然垂放、掌心空。表里长出的道具永远放不下——角色要拿的一切东西都是 prop-design 的独立资产。
        反过来，穿戴类固定特征必须画进表里。判定只问一句：这件东西会不会在本集某一条里被放下、摘下或交给别人？会 → 持握物，归 prop-design，表里手空；不会 → 穿戴类固定特征，它是这个人的辨识特征之一，眼镜、戒指、顶针、腕表、耳饰、袖箍、佩章、常缠的绷带与义肢都在此列，写进 G3 的穿戴槽，形制与戴在身上哪一处一起写死。中途摘下不算固定特征——那是状态变化，走变体。
        双源件的形态归道具板：穿戴件若同时过了 prop-design 的入库判据——有特写、推动剧情、状态会变——它就是同一件东西的两个资产。形态真相源在道具板，角色板照它的形制写、不自拟；生成顺序上这件道具的四视排在本角色 G3 之前，G3 拿它当形态参照。少了这一条，同一枚顶针在角色表和道具板上就是两个样，下游 @ 两张图给出两个答案。
    认错长什么样：
        三格三张脸——没复述同一人；正面全身格带了清晰的头——脸源污染，见下节；手里多出一把伞或一杆枪——道具长进表里，下游永远甩不掉也对不齐；顶针、老花镜这类全片不摘的穿戴件被当持握物剔出表外——此后每次入镜戴不戴由模型即兴；或角色板自己发明了一枚顶针，与道具板对不上；背景出现摄影棚、灯架、墙线——写了 studio 类雷词；背景出现柜台、月份牌、家具这类具体陈设——把场域锚句灌进了资产板，见下面 [中灰底与光]。
    典型例子：
        见 examples/character-example.md 的 G3 条。

[去头 hack]
    怎么认：
        正面全身格从领口以下构图，画面里没有脸。
    为什么：
        广角格里的脸小而糊，而这张糊脸恰是模型会复制进远景镜头的脸源。去头之后，全图唯一脸源 = 大特写格——远景的脸从此只有一个干净来源。
    认错长什么样：
        成片远景里人物五官糊成一团、和特写对不上——回查角色表，全身格带了头。这不是视频侧的错，是资产侧埋的雷。
    典型例子：
        G3 提示词里的固定句式「中格为正面全身、画面从领口以下取景、不含头部」。

[笑/不笑两版]
    怎么认：
        大特写做两版——G1 不笑，默认校验锚；G2 带笑，露齿。笑版由不笑版手术式编辑而来，只改嘴部与眼周、其余像素锁死，不重新生成；母版见 references/variant-and-crowd.md。
    为什么：
        不做笑版，角色第一次在镜头里笑时，牙齿是别人的。
    认错长什么样：
        笑版单独重新生成整张——脸微漂、肤质变；笑版改动块里顺手动了发型或光。
    典型例子：
        见 examples/character-example.md 的 G2 条。

[禁词雷区表]
    怎么认：
        每行按「雷词 → 后果 → 正向替代写法」排——
            studio → 画出真摄影棚 + 把棚灯烤进资产 → 写「纯中灰色无缝背景，画面中除人物外空无一物」。本规则集纯正向，"no studio, no equipment, no walls."（无摄影棚、无设备、无墙。）类禁令一律改写为对空背景的正向描述。
            overhead key light（顶部主光） → 画出灯本身 → 写「柔和均匀的定向光从一侧打来，影调过渡自然」。
            rim light（边缘光/轮廓光） → 烤进资产后不再响应场景光，每个镜头都带着这圈光 → 不写任何轮廓光、逆光效果。
            character reference sheet、painterly → 写实项目触发插画感、概念设定画风 → 写「角色定妆照/定妆设定图」这类照片系措辞，对应英文安全词 "film character sheet"、"studio photographs"。
            画幅、分辨率、--ar 类参数 → 平台参数入了正文会被当画面内容 → 一律在即梦平台 UI 设置。
    认错长什么样：
        角色进夜景仍带着一圈白边——rim light 烤进了资产；每个镜头背景都隐约有灯架——studio 烤进了资产；写实片的角色表出成了手绘概念图——reference sheet 触发插画。

[中灰底与光]
    怎么认：
        纯中灰色无缝背景 + 柔和均匀的定向软光，全片所有角色表统一；背景是空的——画面中除人物外空无一物。
    为什么：
        中灰是曝光中点，不向资产烤入任何光色倾向，资产进任何场景光都能正确响应；软光交代肤质与衣料垂坠而不制造记忆性阴影。纯白底版式随三格法一并弃用。
        空场同理：角色要走进全片每一个场景，板上留下的任何一件陈设都会跟着他走进所有场景。visual-style 的通用基准段——媒介质感 / 色域 / 光逻辑 / 镜头性格四件——可以逐字嵌，承载具体陈设与时代物证的场域锚句不许嵌：一句「一间当铺，柜台是齐胸的黑漆木栅」跟在中灰底版式句后面，就是同一张板上一边说空无一物、一边支起一间屋子，模型两头取平均。
    认错长什么样：
        底色带了青灰、暖白一类颜色倾向——那是把调色烤进了资产，调色属于通用基准段与场景光的事；中灰底版式句后面跟着一间具体房间——场域锚句串进了角色板，时代该由服装形制承担，不由背景陈设承担。

[生成顺序编码]
    怎么认：
        每个角色包内条目带生成序号 G1/G2/G3/G4+，包末附「生成与验证注记」。
            G1 大特写 · 不笑 = 校验锚。先生成，与密版逐维对照——脸型、五官 3–4 点、肤质、发型；锚不对改词重出，锚定了才许往下。原始特写从此不再整体过模型——"The original close-up portrait stays untouched."（原始特写肖像保持不动。）
            G2 笑版 = 手术式编辑自 G1 成图。
            G3 三格表 = 以 G1 成图为参考图同源生成，表中特写格 = G1 那张脸。
            G4+ 变体 = 手术式编辑自 G3 或 G1：改服装/全身状态用 G3 当底图，只改脸部状态用 G1，视变化部位选底图。
    与验证环的关系：
        3.0 流程内无生成验证，正式批量前的稳定性抽测——不同动作/景别多次生成可辨认、与同框资产合测，压力测试标准是 10 次生成 10 次可辨认——由 06-motion-prompts 头部「生成顺序与校准」小节的生成期验证环承载。本站的责任只有一条：把顺序与对照要点写进包内注记，让验证环有据可依。
        崩了先改词；同样问题再犯就重造资产——用户带翻车图回来走 retake，路由回本站。
    认错长什么样：
        先出了三格表再出特写——锚在后，错了全部重来；变体拿密版重新生成整张——纹理全变。

[投喂侧注记 · 平台图像参数唯一真相源]
    平台图像参数以本节为全库唯一真相源，改数只来这里改；prop-design 四视法、scene-design 角度覆盖等处出现的同名数值一律是只读副本，平台改限值只改本节、再让副本对齐：
        - 2.5 图片输入宽高比限 (0.4, 2.5)、边长限 (300, 6000)px；出图画幅本身走即梦平台 UI 参数、禁写进正文；三格横排建议 16:9，落在限内。
        - 投喂稳定性排序：多张单视角图 ＞ 单张多视角图——一张图塞多视角比多张单视角更容易崩。
        - 不归本节：一条视频里挂几张参考图是编译期预算，判据在 control-image 的 type-selection.md。
    三格表是生产侧锁一致性的工具——一张图三格 = 同一次噪声；投喂视频生成是另一回事，按上面的排序办。
    多主体同框或重点镜头，建议把三格表裁成特写/正身/背身各一张的单视角分图再作参考图上传，裁格提取法见 control-image 的 grid-method.md。
    上传顺序与 @图N 归 motion-compile：编译期按该条【参考资产绑定】段 @ 首次出现顺序定死、登记进该条条头【上传清单】，本站与本卡不预设。

[三格法与七维公式的分工]
    三格法管「图长什么样」——版式、脸源、光底、生成顺序；七维公式管「文字怎么写」——密版与提示词主体描述的内容骨架，见 references/seven-dim-formula.md。两者在 G1/G3 提示词里合流：版式句来自本卡，人物描述来自七维精选。
