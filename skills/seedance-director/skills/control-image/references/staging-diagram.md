[定位]
    站位图（staging reference / blocking map）是一张刻意示意化的细轮廓彩色线稿：白底、极淡网格、每个人物一根细线薄色轮廓——一人一色，色彩只做身份。
    它告诉模型"谁在哪、什么姿态、朝向哪"——除此之外什么都不交付。图上绝无字母、文字、标签。设计目标：以最小风格质量携带最大几何信息，因为图纸风格渗入成片是本方法的头号敌人。

[三层防渗架构]
    渗漏有三条进水口，三层各堵一条：
        1. IMAGE 层：人物画成细轮廓、无填充、哑色。线条读作「图纸」，大面积色块读作「美学」——填色即渗漏。网格保持极淡：网格是给作者设计轨迹坐标用的工具，不是给模型的信号。
        2. TEXT 层：connector 绑定块只写正向句式，只声明风格从哪里来——场景参考与角色参考。模型对否定弱——"'no flat illustration' still injects flat."（写「不要扁平插画」照样把「扁平」注入上下文，否定即召唤。）因此绑定块从头到尾不提图纸的图形风格，只有一句法定例外：asset-binding [控制图绑定] 给站位图与轨迹图定死的那句排除句——不得把图上的线条、色块与网格渲进画面——它治的是本类型头号废镜形态，逐字照抄、不扩写。除这一句外，图形词汇只存在于一个地方：站位图生成提示词——那段文字永不进入视频上下文。
        3. STRUCTURE 层：站位图永远最后附加，排在场景参考与角色参考之后，让照片级参考主导风格投票。
    总纪律："Never trade signal for stealth."（绝不用隐身换信号。）——把整张图淡到近乎不可见，防渗与站位信息一起丢；只削风格质量，即细轮廓、哑色、淡网格，不削信号对比度。

[空间事实的来源 · 不在本卡发明]
    机位侧、180° 轴线、每人绑定的地标、frame-left/frame-right 方位——这四件是本场空间的既有事实，一律从 03-shots/epNN-shots.md 本场场头的【空间地图｜epNN-sXX · 场景名（scene-NNN）】块**逐字取用**。该块固定七行——机位侧 / 轴线 / 地标绑定 / frame 方位 / 可见范围 / 排布变化 / 重述规则，形态母版是 scene-design 的 spatial-map-template.md [空间地图块母版]，本站只读不改。该块由 shot-design 随各场落表装载 blocking 实例化、经镜头表审与 ★表确认，是本场空间的唯一真相源；本卡的图解与 connector 块只把它翻成图与句：图解按它摆轮廓，允许把 frame-left/frame-right 换算成图面上的画框分位；connector 块按它写位置行，地标名、朝向与距离措辞逐字照搬，不同义替换。
    块里没写到的空间事实——比如某人的朝向、某个新地标——回 shot-design 补进场级块，不在本站自拟。自拟的后果是确定的：站位图的轴线与 motion-compile 恒定层贴的空间地图块不是同一套，图与文字互相打架，模型两边都不信。
    本场若无场级块——单人条、无走位条——本来就用不上站位图，走 type-selection 的直通或类型 1。

[两步工作流]
    1. 站位图生成提示词。
        输入是一张源帧：关键帧、资产图、或用户提供的构图参照。源帧必须与场级块声明的机位侧同侧——源帧选了另一侧，画出来的图就是越轴的图。源帧作为垫图附给图像生成，但必须被作用域限定：仅作构图指引（COMPOSITION-ONLY）。文字仍要把每个人物的位置、姿态、朝向、锚定几何逐一写明，位置与朝向照场级块的地标绑定行写，只把 frame-left/frame-right 换算成图面上的画框分位——文字承载站位，垫图钉住轮廓。生成提示词母版——图像侧上下文，图纸风格词只在这里成段出现；负面参数语法已适配为句内文字：
            垫图仅作为构图指引使用：精确复制其画框、机位角度、裁切，以及每个人物的位置、姿态与比例；但不复制其摄影质感——不要照片纹理、不要写实光照、不要写实面孔、不要沿用垫图色彩。不得添加任何垫图中没有的内容（Do NOT add anything that is not in the attached image）。不得补全被画框裁切的身体（Do NOT complete cropped bodies）——垫图里被画框边缘切掉的部分，画中同样切掉。
            输出为一张平面示意线稿：白色背景，极淡的浅灰细网格，风格明显示意化、非摄影。人物画为干净的细轮廓线，使用哑色（哑蓝/哑橙/哑黄/哑紫/哑红/哑绿，每人一色，色彩仅区分身份）——无填充、无实心色块、无阴影、无质感、无写实、画面中不出现任何文字字母或标签。
            正视图，与垫图取景完全一致：共{{N}}个轮廓人物。
            {{逐人一行：画框内位置——哑{{色}}轮廓人物，可见范围（全身/仅头肩/仅躯干与手臂），姿态与垫图完全一致（坐/立/仰头/张口/背对镜头），朝向，标志性道具画为简单轮廓形状并钉在与身体的确切相对位置。}}
            {{锚定家具/建筑画为简单细轮廓形状及其位置；或写「无家具，空背景」。}}
            {{背景群像如有：极小的淡灰剪影，写明所在画面区域；无则省略。}}
            此外无它——无地平线、无多余道具、无多余人物。简单、可读、图示化。画幅比例与源帧一致。
        逐人描述的四个必查陷阱，每次交付前过一遍：
            1a. 被画框裁切的身体必须「描述为裁切 + 禁止补全」双保险。
            1b. 头部角度与视线方向写明仰头多少、脸朝上还是朝向对手。
            1c. 道具高度钉在解剖位上，正向 + 对比双写——"across the THROAT, under the chin — not the chest."（横在喉部、下巴之下——不是胸口。）
            1d. 任何手痒想补进去而源帧里没有的东西——不加。
        随图解一起交付：
            - 编号：产出卡记 ctrl-epNN-sXX-cN-stg-vN，绑定块引用去掉版本后缀的 ctrl-epNN-sXX-cN-stg。05-control-prompts/epNN-sXX-control.md 的产出卡就是控制图的单一登记处，不另写进资产索引。
            - 色键一行：写明每种色在源帧里对应谁，例：哑蓝 = 被缚的士兵，中景前部。色键留在本文件内，改图与绑定都靠它。
            - 场级块出处一行：注明机位侧与轴线取自哪一场的场头块，供审核对账。
    2. connector 绑定块——视频侧上下文，单块自足一次粘贴。
        块内每个编号只出现一次：场景、角色、道具在同一段里各有自己的绑定条目、由 motion-compile 写，本块再 @ 一次就是同一 tag 的第三次出现，生成拒绝启动；要指回它们一律用「场景参考」「角色参考」与可视特征代称。字母句柄也不带 @ 前缀——@ 在成品里是上传地址，两者共用一个符号会让模型去找一张不存在的「@A 图」。本段是只读副本，真相源在 motion-compile 的 asset-binding.md [定位] 铁律 1 与 [控制图绑定] 的站位图形态。
        母版由 motion-compile 编译 F1 第 2 段时整块取用——句式照搬，块内项目编号由它翻译成该条的 @图N：
            @ctrl-epNN-sXX-cN-stg 作为【站位】唯一参考（POSITION REFERENCE ONLY，仅作站位参考）：仅用于读取每个人物在场景中的位置、姿态与朝向。画面的一切视觉质量——风格、光线、调色、面孔、服装、环境、道具——全部且只来自场景参考与各角色参考。成片为完全写实的实拍级画面，不得把该参考上的线条、色块与网格渲进画面。

            字母图例（字母只存在于本提示词内，参考图上没有字母）：
            A = 该参考上的哑蓝人物 = {{可视特征代称}} → {{位置：具体点位、姿态、朝向}}。
            B = 该参考上的哑橙人物 = {{可视特征代称}} → {{位置}}。
            {{每人照此格式续}}

            渲染规则：把真实的写实人物——各以其角色参考为准——放入真实场景中本参考所定义的位置上，除位置外不从本参考取用任何内容。

            锁定：全部风格、光线与质感只来自场景参考与角色参考；本参考只定义位置。参考图上的色彩仅在该图上用于区分谁是谁（The colors identify WHO IS WHO on that reference only）——服装与调色以角色参考与场景参考为准。所有人保持站位锁定的位置，直到各自的剧本动作开始。
        块内位置行逐字沿用场级块的地标绑定与 frame 方位表述，全部写可测量语言：一米之内、背贴墙、手扶桌沿；旁边/附近/周围这类弱空间词禁用——本行是最低要求的只读副本，弱空间词完整禁令表的真相源在 blocking 的 spatial-language.md [判据卡 · 弱空间词禁令]，本站落笔时就按这套语言写，不留给编译时再对齐。
        作用域默认全条——人物站位在整条里都成立，不写作用域句；只有当这张图仅对某几镜有效——条内换过一次站位、后半段有人离场——才加一句「本参考用于镜头K–镜头M」。
        附加顺序注记随块交付，写在围栏外、不随块复制进视频上下文：场景参考与角色参考在前，站位图最后。

[核心规则]
    - "Letters live in prompt-space, colors live in image-space."（字母活在提示词空间，色彩活在图像空间。）图上只有彩色轮廓，没有字母——渲染出的字母会渗进画面；字母在 connector 文字里经色彩绑定到人物，既保留「A 猛地扭头」这类稳定句柄，又零渲染风险。
    - 一人一色，哑色，彼此色相拉满距离。色彩 = 字母的身份，永远不是服装。轮廓，永远不填充。
    - 永远是摄影机一侧的正视图，绝不用俯视平面图——"Video models think in frames, not blueprints."（视频模型按帧思考，不按图纸思考。）
    - 姿态是几何，裁切也是几何：异常姿态照实画——倒挂、背对镜头、头埋进手掌——被画框切掉的人物照实切。
    - 图解上的小误差可以容忍——图例文字覆盖图面误差，legend 判高于图。
    - 版本纪律：每次返工在产出卡 bump -v2/-v3，绑定块永远写不带版本后缀的编号串、自动解析到产出卡上的活跃版本。作废的那一版必须在产出卡里标废、不进条头上传清单——作废图仍被上传就是幽灵站位（ghost blocking）。

[改图两规则]
    1. 重生成永远回喂原始帧，绝不回喂上一版图解——喂图解会复制图纸缺陷。
    2. 改稿口令用「色彩 + 动作」，不用角色名：说"把哑蓝人物右移到桌角"，不说"把陈默右移"——色键在本文件里，角色名的绑定发生在 connector 层，图像生成侧只认识色。

[扩展 · 同一约定]
    - 轨迹图：子弹、抛物、飞鸟或人物走位的路径，在淡网格上按真实坐标设计，以虚线彩色路径画在图上——一条路径一种哑色。图例四要素逐条绑定：起点（START）、路径形状（PATH）、终点（END）、触发拍（TRIGGER）——例：虚线哑红 = 子弹路径，从 B 拳侧出发，平直，出画右，枪响即发。
    - 镜头路径图：箭头标注推轨/摇移方向，图例声明「箭头 = 仅镜头路径」。
    - 走位图：人物移位画虚线，如 A → 新站位点；图例写明起点、路径、终点位，以及移动发生在哪一句台词/哪个动作拍上。

[QA 双清单]
    图解生成后、指定编号前，查图：
        - [ ] 机位侧、180° 轴线、每人的地标绑定与相对方位，与 03-shots 本场场头的场级块对得上——图上是画框分位、块里是 frame 方位，换算后必须同指一处；对不上就是两套空间。
        - [ ] 只有细轮廓——无实心填充、无色块、无阴影。
        - [ ] 图上任何位置无文字、字母、标签。
        - [ ] 裁切保持裁切——没有被补全的头、凭空的头盔、多出的家具或人物。
        - [ ] 道具在源帧所示的确切解剖高度与位置——喉部还是胸口，差之即废。
        - [ ] 姿态与源帧完全一致：头角度、视线方向、口型开合、异常姿态。
        - [ ] 画框与裁切匹配源帧构图与画幅。
    视频生成后，查成片：
        - [ ] 完全写实——画面任何角落无平面感/图形感。
        - [ ] 无白底或网格残迹、无线稿边缘。
        - [ ] 人物服装、盔甲、调色中无站位图用色。
        - [ ] 画面中无字母或任何排版元素。
        - [ ] 每个人物在图定位置、朝图定方向，直到其剧本动作开始。
    任一项失败 → 回到渗漏那一层修：图层 → 轮廓再细、色再哑；文字层 → 从视频侧文字剔除图纸风格词，只留那一句法定排除句；结构层 → 站位图改到最后附加。修完 bump 版本号。

[判据卡 · 该上站位图]
    怎么认：
        画面内 ≥3 人、或 2 人但有交叉走位/换位、或人物朝向与视线关系是戏剧重点——对峙、包围、背对。纯文字描述多人位置在调研中的确证失败模式是「位置每几秒重排一次」。
    认错长什么样：
        - 图上写了 A/B/C 字母帮模型认人——字母被渲染进画面；身份绑定该走色键 + 图例。
        - 人物涂了实心色块"更醒目"——色块 = 美学信号，渗成蓝衣服；色 → 服装渗漏是已知失败。
        - 画了俯视平面图"更清楚"——模型不读平面图，站位全失效。
        - connector 里写"参考图是线稿示意图，不要画成线稿"——否定即召唤，「线稿」进了视频上下文；块内唯一许写的否定是那句线条/色块/网格排除句。
        - connector 里把场景与角色编号再 @ 一遍——它们在绑定段里已各有条目，块内这一次是第三次，生成直接拒绝启动；指回它们用代称。
        - 站位图排在角色参考前面上传——图纸主导了风格投票，整条发灰发平。
        - 返工时喂上一版图解改——图纸缺陷代际复制。
        - 不看场头场级块、照着源帧自己判轴线与机位侧——图上的 180° 线与编译层贴的空间地图块反向，成片左右互换。
    典型例子：
        三人仓库对峙：场级块给定机位侧与轴线 → 源帧 = 条 c2 主机位关键帧、与该机位侧同侧 → 生成提示词逐人三行——哑蓝/哑橙/哑绿——加桌子细轮廓锚定 → 色键一行 → connector 三行图例把三色各绑到一个可视特征代称、块内不 @ 角色编号 → 锁定段收尾 → 附加顺序：scene-004、三张角色参考、关键帧、站位图最后。完整成品见 examples/control-image-example.md。
