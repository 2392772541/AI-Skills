# 多候选图与版本管理交互机制说明 (Image Candidates & Versioning)

## 1. 现象剖析：为什么“选了 4 张候选图，但当前只显示 1 张”？
1. **下拉框的语义是“生成参数（Target Count）”**：
   - 节点顶部下拉菜单中的 `1 张` / `2 张候选图` / `4 张候选图` 是为下一次点击 `▶ 生成图片` 预设的请求参数（对应 API 的 `n` 字段）。
   - 它**不是**指示当前卡片里已经堆叠了多少张图。
2. **当前图是“初始单张底图”**：
   - 工作流初始化导入时，卡片内绑定的是由九宫格大图裁剪出的**单张切图资产**（尺寸通常为 941×1672 或 720×1280）。
   - 因为尚未针对该镜头执行过“4 连发批处理生成”，所以卡片内只有当前这 1 张主图资产。
3. **前端渲染触发条件（app.js 源码逻辑）**：
   - 当点击 `▶ 生成图片` 触发本地 API 或绘图模型后，如果后端接口返回了包含多个 URL 的数组：
     ```javascript
     if (n.data.candidates && n.data.candidates.length > 1) {
       // 自动展开 4 宫格缩略图列表 (.candidates-grid)
       // 带有绿色高亮边框，用户点击任意一张缩略图，即可将该图设为主图资产
     } else if (n.data.asset?.url) {
       // 仅渲染单张主图
     }
     ```
   - 只要接口返回 `data.length > 1`，界面就会自动切换为多候选图选择网格！

## 2. 版本与质检交互规范
- **版本归档（Versions）**：多次点击生成会生成 `V1`, `V2`, `V3`...，保存在 `n.data.versions` 列表中。用户随时可以通过【版本下拉框】回滚到历史版本。
- **质检标记（Quality Gate）**：只有点击【√ 质检合格】或系统评估通过后，该图才会标记为合格，并安全向下游视频生成节点传递。
- **独立单镜重绘保护**：重绘某一镜的图片时，绝不影响其他镜头的既有资产与视频，保障各镜头隔离。
