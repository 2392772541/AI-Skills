[任务]
    读 02-breakdown/epNN-breakdown.md 的人物清单，为每个标「新增」或「变体」的角色产出图像提示词包：大特写校验锚不笑版 → 笑版编辑条 → 三格角色表 → 变体编辑条，整包编码生成顺序，每条复制即可到即梦平台出图。
    同时为每个角色完成三件登记：短串管行内身份锁，密版管出图与台账反查，声线锁管有台词角色的语音身份。三件只写进 04-assets/reference-index.md 角色段一处，下游只引用不另起。
    「复用」角色跳过，沿用既有编号与参考集，不重画。
    两种调用场景：
        - 资产包一次性：与场景、道具同批——拆解清单的核心与边角角色全量建档；三站出齐派资产审，审过随包交 ★资产确认。
        - 增量模式：表审后反推出的新增角色与变体、retake 产生的新状态——按需补做并登记；冒出清单外的核心级新角色 = 拆解遗漏，回拆解补清单再建档，不静默处理。
    0-1 还是迭代由产出物存在与否判定：04-assets/characters-prompts.md 不存在走 0-1 全量；已存在只追加本批，既有条目一字不动、标清集数。
    规则集声明：本站属图像提示词规则集，一切生成提示词只服从这一套，与视频提示词规则集双规则集隔离、禁止串用，隔离理由是 "the rules of one job poison the other."（一条链路的规则会毒害另一条。）正向改写与密度纪律落在这里，越界形态见 [禁止] 前三条：任何禁令改写为期望态——要「干净的干燥皮肤」不写「没有痘」，NOT 堆叠会注入被禁概念本身；主体描述写紧凑散文，宁短勿膨胀——每多一个不带信息增量的子句都在稀释注意力，删掉不改变画面的句子。

[第一性原则]
    本环节是【导演思维】第 3 问「一致性」的展开：把角色的脸、身、声一次定档成可逐字复用的资产对，即文字加图，此后所有镜头只引用、不再发明——一致性是参考问题，不是 prompt 问题。
    资产是一对：文字描述符逐字进下游提示词，图是模型锚定的参照。"An asset is a pair: text plus image."（资产是文字加图像的一对。）两者都从本站出，缺一即残。
    通用基准段逐字嵌入：每条出图提示词开头逐字嵌入 00-bible/visual-style.md 的视觉风格通用基准段——媒介质感 / 色域 / 光逻辑 / 镜头性格四件，角色/场景/道具三方同一段，跨资产画风的唯一锚；不改写、不另起调色。
    角色板是中灰底空场：板上除人物外空无一物，场域锚句与任何具体房间陈设一律不进——一张挂着月份牌、支着柜台的角色板，等于把那间屋子烤进了这个人，此后他走到哪个场景都拖着它。时代靠服装形制落地，不靠背景陈设。
    脸只有一个来源：全身格去头，全图唯一脸源 = 大特写——广角格里那张小而糊的脸恰是模型会复制进远景的脸源，去掉它，远景的脸从此只有一个干净来源。
    底图像素不可变："The base image stays the same pixels."（底图保持同一批像素。）变体一律蒙版点改原图，图片从不整体过第二遍模型，皮肤纹理才能存活；新版本永不覆盖旧版本。
    清单优先：一切角色来自拆解清单，不自行增删；角色手里的持握物一律是 prop-design 的资产，本站不发明道具。
    短串要短：短到下游愿意原样行内引用——长了下游会自己重描而漂移；密版永不进动态提示词成品。
    生成顺序即质检：包内编码「特写先行」——大特写是此后一切资产的校验锚，锚不对不往下生成；验证环本身住 06-motion-prompts 头部「生成顺序与校准」小节，本站的责任是把顺序与对照要点写进包内注记。

[输出风格]
    直接给可复制的成品提示词包，不逐条解释设计理由，需要才说一句取舍。
    中文叙事段落，先整体后细节，短句分层。命令式、信息密度高。
    每条提示词自带生成序号、底图归属与出图要求，让用户不看上下文也能按 G 序照着出图。
    典型表达：
        - "G1 先出，锚不对不往下"
        - "三格必须同一张出，分开出必漂"
        - "复用 char-001，不重画"
        - "他手里那把伞归 prop-design，表里手空着；胸前那副摘不下来的老花镜照画"

[模式与开关]
        - 判定调用场景：资产包一次性，还是增量补做；0-1 还是迭代，看 04-assets/characters-prompts.md 是否存在。
        - 本站产物随资产包出齐派资产审，审过合并交 ★资产确认；站内不逐件找用户。

[读上游]

        - 00-bible/visual-style.md：复制通用基准段备嵌，逐字、不改写；[依赖检测] 列的五个字段一并取出备用，服装年代形制从「时代与世界锚」的年份/地理与服装形制取、不自拟，场域锚句不取。

        - 新增 → 走 [新增建档]。
        - 变体 → 走 [变体建档]。

[新增建档]
    每角色六件事，方法见对应 reference。
        1. 起草密版：按七维公式全维填满，方法见 references/seven-dim-formula.md；写实项目肤色维挂强制保真后缀；服装维锚定时代形制——时代即法律，资产期锚死。
        2. 蒸馏短串：从密版提一句话——年龄 + 关键面部 + 发型发色 + 标志服装，一句写完。
        3. 写提示词包，判据见 references/three-panel-method.md：
            - G1 大特写 · 不笑——校验锚，三四分之三视角，中灰底软光。
            - G2 大特写 · 笑版——手术式编辑自 G1 成图，只改嘴部眼周。
            - G3 三格角色表——以 G1 成图为参考同源生成：大特写格 + 正面全身去头 + 背面全身，手空；全片不摘的穿戴件照画，双源件的形态以道具板为准、本条排在该件道具四视之后。
            - 每条开头嵌通用基准段，主体描述紧凑无堆砌，禁词零出现。
        4. 定声音：有台词角色写声线锁，公式见 references/voice-lock.md；核心角色在角色块预留「表演档案」段，挂点与「表演气质」对账口径见同卡末节，母版住 performance/，本站不复制其规则。
        5. 查角度覆盖需求：对拆解讲戏本与已有镜头表反查有无俯拍特写、仰拍等特殊角度，有则登记进「角度覆盖」栏的需求侧，默认三格已覆盖。
        6. 登记：按全库唯一母版 script-breakdown 的 reference-index-template.md「角色」段的条目骨架逐字段填齐 reference-index 角色块，不自创字段。

[变体建档]
    判据与母版见 references/variant-and-crowd.md。
        - 先过状态升格判据：跨条持续且影响辨识的外观变化才升变体；单条内瞬时状态留给动态提示词散文。
        - 写手术式编辑提示词：基于原版成图，只改变化点，PRESERVE 穷举锁死其余。
        - 编号 char-NNN-vN，附语义状态标签——装束线 → 临时状态 → 位置态叠加，谱系字段写明父版本与变化点。
        - 密版增量只写变化点 + 「其余同原版」。声线锁不随外观变体改变。

[群演]
    写法见 references/variant-and-crowd.md 群演节。
        - 本场人群建一个群演资产，不逐人建档：写身体的质量与局部，不写人数；群演图不许出现清晰可辨的脸。

[落盘]
        - characters-prompts.md 追加本批角色包，既有条目一字不动、标清集数与调用场景；登记块进 reference-index 角色段。
        - 每个角色包末尾附「生成与验证注记」：G 序号顺序、G1 对照密版的要点、指向 06 头部「生成顺序与校准」小节的生成期验证环。

[自检]
        - 对 [完成标准] 逐条过；禁词扫描——studio、顶光灯具、边缘光、插画触发词；双规则集扫描——无负面措辞、无镜头N/时间戳/运镜序列/转场语。

[完成标准]
    确定性自检动手做：本站产物里可数、可对照的项逐一核过，不凭「看起来对」；查出的当场修，修完才交。
    1. 每个「新增」角色有完整提示词包：G1 特写锚 + G2 笑版 + G3 三格表，每条开头逐字嵌通用基准段、整条可直接复制生成。
    2. 三格表正文双保险复述「三格同一人」；全身格去头、手空、中灰底软光、禁词零出现；全片不摘的穿戴件已画进表里、双源件形态与道具板一致；板内除人物外空无一物——零场域陈设、零场域锚句，群演质感板除外，它只许带一层承托面。
    3. 三件登记齐：短串一句，下游可原样行内引用；密版一段，七维填满、具体到碎发怎么贴与服装磨损纹样；声线锁引号整块，沉默角色标「无」。
    4. 每个「变体」是手术式编辑条：只改变化点、PRESERVE 穷举；编号 char-NNN-vN、谱系可追溯到原版、语义状态标签在。
    5. 群演按一个资产处理，无人数、无清晰脸。
    6. 编号规范：char-NNN 跨集不变，新状态 = 新变体永不覆盖；本站不预设 @图N 上传顺序——顺序由 motion-compile 在编译期按该条【参考资产绑定】段 @ 首次出现顺序定死、登记进该条条头【上传清单】。
    7. 生成顺序编码在包内，G1 → G2 → G3 → G4+，且附验证注记指向 06 头部「生成顺序与校准」小节的生成期验证环。
    8. 核心与边角一并按拆解清单出齐；冒出清单外的核心级新角色已回拆解补清单再建档。
    9. 交接测试：把 reference-index 角色段交给 control-image、motion-compile，它们不回看 characters-prompts.md 正文，仅凭 @编号 + 短串——台词条再加声线锁引用——就能锁定每个角色；做到即够，停。交付前另对照 examples/character-example.md 的密度核一遍。

[禁止]
    - 禁止双规则集串用——症状驱动负向、【针对性负向】、块序、镜头N、时间戳、运镜序列、转场语，视频提示词规则集的东西出现在本站任何提示词里即为缺陷。
    - 禁止生成提示词出现「不要/没有/禁止/no/not」类负面措辞——一律正向改写；编辑提示词是唯一例外区，允许结构化改动块，删除操作必须配填补物。
    - 禁止写雷词——studio 会画出真摄影棚并把棚灯烤进资产；overhead key light 会画出灯本身；rim light 把边缘光烤进资产、此后不再响应场景光；character reference sheet 与 painterly 在写实项目触发插画感；画幅/分辨率是平台 UI 参数，禁写进正文。
    - 禁止角色表里画持握道具——手必须空着，表里长出的道具永远放不下；穿戴类固定特征不在此列，全片不摘的它必须画、且形态照道具板；禁止把场域锚句或任何具体房间陈设写进角色板——中灰底空场，背景里长出的屋子和道具一样永远放不下；禁止全身格带清晰头脸——去头铁律。
    - 禁止覆盖或修改既有资产条目与旧版本图——新状态 = 新变体，追加不覆盖；禁止变体整表重新生成——一律蒙版点改。
    - 禁止把密版或长相重述搬进下游动态提示词；禁止把短串写成一段。
    - 禁止群演写具体人数——超过 15 人必塌缩成三五个人形；禁止为群演逐人建档。
    - 禁止真人姓名与角色名入提示词——一律转译为特征描述，这条提示词本来就是在定义这个人长什么样，名字对模型是空词，判据见 motion-compile 的 asset-binding.md [人名与代称 · 六条铁律]；禁止品牌与版权 IP 元素。
    - 禁止自行增删清单之外的角色；禁止替 scene-design、prop-design 二次发明它们的资产。
    - 禁止声线锁逐条改写措辞——连同义词都不换，换措辞就扩大采样范围导致声音漂移。

[被调用方式]
