# 融合人物资产工序

先读根入口的制作主线及 `references/character-method.md`，使用 `assets/character-card-template.md`。本文件替代来源包 character-design 的强制三格、七维全填与笑版要求。

## 输入

读取指定原文和拆解中的角色清单、已采纳风格、既有资产索引、必要的连续性记录。原文缺某外貌项标未知；不得为了补模板虚构事实。已有角色复用身份；新增服装或持续伤势做变体；发现此前漏掉的关键人物先补拆解。

## 操作

1. 按小墨六项要素提取原文，记录证据、推导和建议。合并别名，检查是否真为不同人。
2. 写一段人物白描及一句短串。按需要补体型、步态和习惯动作；身份描述不绑定某一场的表情、光线或背景。
3. 在 `04-assets/reference-index.md` 统一登记角色 ID、父版本、外观、识别点、服装版本、临时状态、声线需求、关联道具和来源。
4. 写面部身份参考提示词，然后按计划镜头决定补哪些角度和装束图。常用的三格、局部编辑、群演方法可参考下列资料，不能当作平台保证。
5. 交付提示词时标图片待生成。拿到图片后对照具体识别点审核，登记真实路径、用途、版本、状态。
6. 镜头与编译环节只引用已登记角色和变体；发现图片与原文冲突回修人物资产，不用视频提示词偷偷“补脸”。

## 按需参考

- `references/seven-dim-formula.md`：有需要时补充身份与材质细节，忽略机械全填和固定词语数量。
- `references/three-panel-method.md`：研究三格版式、特写及全身分工，平台能力由融合适配文件决定。
- `references/variant-and-crowd.md`：变体、群演及局部编辑思路，保留原图但不假定像素不变。
- `references/voice-lock.md`：有台词且需要模型生成声音时使用，无配音项目标无。
- `templates/character-prompt-template.md`、`examples/character-example.md`：仅借鉴结构，按本版实际需要删去无用条目。

## 验收

六项外观信息的已知与未知清楚，所有补充有类别，角色能区分；编号唯一、变体有父版本；道具与场景交叉引用有效；描述、参考图、镜头表一致；提示词和已生成图像不混淆。少人物项目不为了完整性生成无关资产。
