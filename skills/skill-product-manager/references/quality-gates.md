# 按改动选择验证

完成标准是用户要求的功能和可核验证据。验证强度随改动范围、失败后果和已发现问题调整；通过相关检查后停止，不为增加次数重复全套测试。

| 改动 | 必要检查 |
|---|---|
| description／触发边界 | frontmatter 解析；有代表性的正向、负向、相邻技能冲突样例；受影响路由回归 |
| 根文档／渐进式披露 | 所引用文件可达；所需约束保留；只读匹配分支足以执行；不要求通读全部参考 |
| 脚本 | 语法和受影响的现有测试；真实成功路径及相关失败路径，使用临时 fixture |
| 安装／去重／启用配置 | 完整文件比较；识别软链接与独立版本；配置解析；实际技能加载回读；回滚后哈希一致 |
| 外部能力／权限／生产写入 | 核查来源、依赖和授权边界；高后果失败场景按需求做行为验证；未经授权不为测试触发真实外部写入 |

## 发现与边界

description 简短说明能力和准确触发条件，不塞全流程。避免“提到任何链接／任何视频就强制使用”等过宽条件。正文说明相邻任务的分工，用户已有框架与明确输出优先。
正向、负向和冲突样例用真实表达；数量按覆盖需要确定。启发式路由排名只证明脚本结果，模型是否正确选择和执行必须用实际模型任务另行验证。

## 授权与持续执行

在已有授权范围内完成读取、可回滚修改、测试和必要重试。新出现的不可逆／破坏性影响或必要秘密传输需要单独确认时，说明具体动作与影响。不要把阶段名、模板或评分当成用户审批要求。
只询问阻止安全完成的关键信息；可从文件得到的事实先直接读取。保留人工编辑，修改正式文件先备份，使用 diff 和回滚记录。

## 可观察失败信号

- 未执行验证却声称通过：标记未执行，补充影响结论的验证。
- 只给方案或样例就宣告执行任务完成：继续运行、检查并修复本次引入的问题。
- 为普通小改动强制生成测试或反复跑全套：使用已有相关检查；无相关测试时如实说明人工检查与限制。
- 隐去原有失败或把结构分数当成效果证明：分开报告基线失败、新回归、实际模型行为与未执行项。

结构层检查 frontmatter 和链接；路由层检查正负与冲突；行为层用隔离 fixture 检查实际产物和工具调用；涉及高后果或新增执行边界时再加入压力／失败诱导。文案修改不必为满足表格而创建无关运行测试。
