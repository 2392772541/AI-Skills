# 转录文档学习系统

把口语化、重复多、可能含有 ASR 错误的中文培训转录稿，整理成可阅读、可实践、可复习、可连接到 Obsidian 知识库的学习资料。不要把任务当成摘要或逐字稿排版；目标是恢复课程结构并把“听懂”转成“能做、能解释、能复习”。

## 处理契约

始终区分证据层级，禁止把推测写成事实：

- `课程原话`：转录中明确说出的观点、步骤、案例、定义或数据。
- `结构化提炼`：对原话的压缩、归类、去重，不改变含义。
- `实操延伸`：根据课程方法给出的可执行建议，必须标为延伸。
- `待确认`：听不清、术语/产品名疑似错误、数字不可靠或上下文不足的内容。

无法确认时保留原词，使用 `【待确认：原文“...”｜疑似“...”｜依据/缺口：...】`，并在“待确认项”集中登记。不要静默改正品牌名、模型名、指标、时间、数字或因果关系。

## 工作流

### 1. 发现输入与边界

1. 找到所有用户提供的源文件，按课程/章节/文件名排序；保留原文件，不覆盖原稿。
2. 识别格式：DOCX/TXT/MD/SRT 直接作为转录来源；音频/视频先生成本地转录文本，再进入本流程。
3. 如果有视频画面或课件截图，保留能证明框架、表格、案例和操作步骤的截图，并在笔记中用 Obsidian 嵌入；没有截图时不要伪造。
4. 确认笔记目录和 Obsidian vault 根目录。用户已给出路径时严格使用；未给出时先使用当前已知 vault，不要把临时工作目录写进最终笔记。
5. 多份材料先建立“课程索引”；单份材料至少生成一份主笔记、复习题/闪卡和待确认项。

### 2. 生成可追溯的文本源

- DOCX：提取正文、表格和标题；保留页码或段落编号作为来源锚点。
- TXT/MD/SRT：保留原始行号/时间戳；先复制一份工作副本再清洗。
- 音频/视频：使用 FFmpeg 提取单声道 16 kHz WAV；优先采用本地时间戳转录，视频流程可参照已安装的 `$lecture-notes`。若使用 OpenRouter 音频转写，先确认 `OPENROUTER_API_KEY`，保存原始 JSON 与 canonical `.txt`，笔记只能以本地 `.txt` 为主要输入。
- 转写失败或 API 不可用时，说明阻塞点并继续处理已有文本；不得凭空补全音频内容。

### 3. 清洗转录稿（不改事实）

按段落处理，保留讲师的定义、转折、例子、演示、提问、作业和强调；删除纯口头噪声：

- 语气词、寒暄、口吃和连续重复；保留改变语义的重复强调。
- 句子未完成时合并上下句，不把多个观点拼成一个观点。
- 课堂闲聊、招聘、设备或无关故事移到“旁支/待取舍”，只有与课程方法有关时才纳入主线。
- 识别错误只在上下文和原图/原音频能够证明时修正；否则用 `【待确认】`。
- 每个重要结论保留来源锚点：`[P03 12:40]`、`[DOCX p.7]` 或 `[原稿第 18 段]`。

清洗后的文本仍应可回溯到原稿。不要把清洗稿当成最终学习笔记。

### 4. 恢复课程结构

先回答“这节课要让学习者会什么”，再组织内容。至少产出：

1. 本节学习目标（3–8 条，可验证、以动词开头）。
2. 主题树：概念 → 原理/判断依据 → 方法步骤 → 案例 → 应用边界。
3. 关键定义、对比关系、因果链、流程、指标和决策条件。
4. 课程案例：背景、任务、做法、结果/结论、可迁移经验；结果未讲出时写“未提供”。
5. “学完后能做什么”：把每个方法改写为输入、步骤、产物和验收标准。
6. 知识地图：只有当关系有帮助时使用 Mermaid；节点名称应能链接到 Obsidian 笔记。

对产品、AI、竞品分析等课程，优先检查这些常见层次是否被混淆：目标/受众、市场定位、技术/模型、功能、用户体验、商业与落地约束。课程没有提到的层次不要假装是课程原内容，可放入“实操延伸”。

### 5. 生成学习系统产物

使用 [output-template.md](references/output-template.md) 作为结构基线；按材料规模选择文件数量：

- 单份转录：`主笔记.md` + `复习题与闪卡.md`；“待确认项”放在主笔记末尾。
- 多份同课材料：`00-课程索引.md` + 每份 `Pxx-主题.md` + `复习题与闪卡.md`。
- 跨课程沉淀：把稳定概念抽成独立原子笔记，并用 `[[双链]]` 连接；不要为了凑链接创造空笔记。

主笔记必须包含：YAML frontmatter、输入与证据质量、学习目标、关键结论、知识地图（适用时）、按主题的详细笔记、定义、案例/示例、实操 SOP、坑点与隐患、待确认项、来源与证据说明。

复习资料必须包含两类卡片，每张只测一个知识点：

- **Recall**：定义、事实、步骤、关系；答案短而准确。
- **Thinking**：为什么、比较、取舍、场景应用、反例或评审；答案写出推理依据。

自测题至少覆盖：回忆题、解释题、对比题、场景题、实操题；先给题目，再用折叠 callout 或“参考答案”分隔答案，避免读者一眼看到答案。待确认数字、术语和观点不得作为已证实事实写入答案或事实卡；可以反过来出“为什么不能采用该信息”的审计题。

### 6. 写入 Obsidian

- 使用 frontmatter（`title`、`course`、`source`、`tags`、`status`、`created` 等），正文使用 Obsidian wikilinks、callouts 和 Mermaid。
- 图片只复制最终筛选的证据截图到 vault 的 `assets/<course-slug>/`；最终笔记不得出现绝对路径、`file://`、临时目录或原始帧文件名。
- 截图说明包含来源文件和时间/页码，例如“图 2：竞品画布（P02，约 03:10）”。
- 不静默覆盖已有笔记或图片；存在同名文件时先比较内容/哈希，采用增量文件名或询问用户。

### 7. 质量门禁

交付前逐项检查：

- 主要主题都能在原稿或截图中找到证据；延伸内容有明确标记。
- 每个学习目标都对应至少一个笔记段落和一个练习/自测题。
- 没有把闲聊、ASR 猜测或 OCR 噪声当成知识点。
- 定义、步骤、案例、坑点、边界条件和待确认项齐全。
- Obsidian frontmatter 存在，代码围栏成对，所有 `![[...]]` 图片可解析。
- 至少抽查三处来源锚点；关键数字、产品名和因果关系回看原文/原图。
- 使用 `scripts/validate_learning_note.py` 做结构检查；有错误先修正再交付。

## 输出风格

用中文、短段落和层级标题；不要输出逐字稿大段复制。优先使用表格呈现“维度—判断问题—证据—结论”，使用 callout 突出“核心结论”“常见坑”“待确认”。把课程观点、你的归纳和外部补充分开，并为外部补充附链接与日期。
