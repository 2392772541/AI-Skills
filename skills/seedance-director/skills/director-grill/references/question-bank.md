[定位]
    这是追问纪律的约束工具，不是问卷脚本。默认走创造性追问，想接受敷衍时翻 [不接受的答案]，想提前停时翻 [接受标准]，想瞎问时翻 [主问题]。
    不暴露 Phase 标签和维度名给用户，那是内部翻题库用的。
    BASIC 模式下不逐维度问：从未达接受标准的维度里挑至多 3 个「错了会导致重新生成视频」的，一次问完，其余按默认拍板写 [假设]。

[五段结构]
    覆盖意图 = 为什么问这维度。主问题 = 默认抛的问题。追问深化 = 用户敷衍时的反击，格式「用户说 X → 你回 Y」。接受标准 = 通过条件。不接受的答案 = 必须驳回的样本。

[Phase 1 · 片种与观众]
    总分轨开关，必须最先过。认错片种，后面每一问都问错。
    片种分轨表：
        五轨及其下游后果，定轨即同时定下这些默认，后续各站按轨取值：
        电影级，即横屏短片或长片：节奏留白可用，画幅默认 2.39:1 或 16:9，质感走胶片或高端数字，条倾向长——情绪长镜可到 8–15s，待实测校准——合规按内容尺度常规线。
        竖屏短剧：3 秒钩子定生死，画幅 9:16，节奏密、切镜快，条倾向短、对白密，合规多一条平台审核线——冲突尺度、擦边。
        漫剧，即动漫或漫画叙事：媒介质感整体切换为风格化渲染，皮肤纹理、微表情这类写实雷区权重下降，风格锁权重上升，画幅随发布平台。
        广告 MV：单一记忆点统治一切，品牌与音乐节奏是硬约束，合规多品牌授权与竞品回避，条以卡点为单位。
        UGC vlog：伪实拍第一人称，手机前摄、翻转镜头、非表演感这类媒介质感块是风格核心而非缺陷，质感块词库归 motion-compile，本站只定轨。
        片种可复合，如「竖屏短剧 + 漫剧质感」，复合时逐项声明每个默认跟哪一轨。
    1.1 · 片种判定：
        覆盖意图：
            片种是分轨开关，决定节奏预算、画幅、质感方向、合规阈值。这是全站第一个必须钉死的决策。
        主问题：
            "这片子是哪一路：横屏电影级、竖屏短剧、漫剧、广告 MV、还是伪实拍 vlog？观众在哪看到它，划走的成本是几秒？"
        追问深化：
            用户说"就是个短视频" → 你回："短视频是长度不是片种。竖屏短剧 3 秒一个钩子，电影级 30 秒铺一个镜头，广告 15 秒卖一个记忆点。你的观众在哪刷到它？"
            用户说"电影感的短剧" → 你回："电影感和短剧节奏有打架的地方。质感可以跟电影走——胶片颗粒、考究的光；节奏必须跟短剧走——观众 3 秒没钩子就划走，长镜头美学正撞在枪口上。质感归电影、节奏归短剧，这个组合你确认？"
            用户说"都行，你看着办" → 你回："片种认错，后面每一问都问错，这个板必须你拍。我给你摆三条命：A 竖屏短剧，快节奏强钩子，靠冲突留人；B 横屏电影级，靠画面和留白说话；C 伪实拍 vlog，第一人称的真实感。你这个故事最像哪条命？"
            用户片种与素材冲突，拿三分钟沉默长镜的本子说要做竖屏短剧 → 你回："你这个本子每场都在留白，短剧观众等不到第 4 秒。要么换片种，要么本子回炉加钩子。选哪个？"
        接受标准：
            五轨或声明清楚的复合轨择一；画幅随之落定；用户知道这一轨的节奏与合规后果。
        不接受的答案：
            "都行、看着办"；"短视频"当片种；复合轨说不清各默认跟谁。
    1.2 · 观众与平台：
        覆盖意图：
            观众决定节奏底线、尺度边界、完播预期；平台决定画幅与审核线。为所有人拍等于为没有人拍。
        主问题：
            "谁看？发在哪？这片子发出去，第一个转发它的人是谁，他为什么转？"
        追问深化：
            用户说"所有人都爱看" → 你回："所有人等于没有人。深夜刷手机的打工人、周末找片的影迷、追更的短剧用户，是三种完全不同的耐心。挑一种。"
            用户说不出平台 → 你回："平台定画幅也定审核线。竖屏信息流还是横屏播放器？这个不定，画幅就是抛硬币。"
        接受标准：
            一个可指认的主观众 + 发布平台 + 完播或留存的预期方向。
        不接受的答案：
            "所有人、大家"；平台留空；观众画像只有人口学没有观看情境。
    1.3 · 意图一句话：
        覆盖意图：
            整个项目的第 1 问：观众看完带走什么。这一句是后面每一站每一次判断的最终依据，也是【导演思维】第 1 问「意图」的取值来源。
        主问题：
            "片尾黑屏那一秒，观众心里冒出来的那句话是什么？"
        追问深化：
            用户说"想做个爽的" → 你回："爽有很多种：复仇打脸的爽、大场面轰炸的爽、反转抖包袱的爽。你的观众是哪一种爽？拿一部片给我锚一下。"
            用户说"感人的" → 你回："观众为谁哭？哭他可怜，还是哭他终于被理解？这两种感人拍法完全不同。"
            用户给了孤独、救赎、亲情这类主题词 → 你回："主题是学者总结的，观众带走的是具体的一下：一个画面、一句话、一个没说出口的动作。你想让他们记住的那一下是什么？"
        接受标准：
            一句可复述的意图，指向可判定的观众反应，不是爆款、百万播放这类虚荣指标，也不是抽象主题词。
        不接受的答案：
            "爽、感人、高级"无锚；拿播放量当意图；一句话里塞三个意图。

[Phase 2 · 风格定轴]
    进入前提：Phase 1 已过。风格字段的落盘规范见 references/visual-style-spec.md，本 Phase 负责把决策问出来。
    影视感受翻译表：
        听到左列的词，禁止直接入库，按右列拆轴逼具体，每翻完一个 recap 确认：
        "电影感" → 拆四样逐个问要不要：画幅——2.39:1 黑边？质感——胶片颗粒？光——有来源的造型光？节奏——留白？
        "高级感" → 王家卫式霓虹暧昧、Deakins 式控制到毫米的剪影、A24 式自然光胶片，三种"高级"先选一种再拆。
        "氛围感" → 氛围 = 光 + 天气 + 声音底。哪个时刻的氛围？拿一帧参考。
        "真实感" → 伪实拍质感走 UGC 轨，还是自然主义打光走电影轨？两条路资产做法完全不同。
        "燃/炸" → 节奏密度还是场面规模？密度是切镜频率，规模是群演与爆点；前者便宜后者贵。
        "治愈" → 色温偏暖 + 光比小 + 运动慢，三个都要还是挑两个？
    2.1 · 参考锚定：
        覆盖意图：
            参考片是风格访谈的硬通货：把抽象审美锚到真实作品，再拆出承重属性。片名是症状不是规格——锚名收下之后必须走 references/visual-style-spec.md 的 [风格锚研究法] 上网研究、蒸馏成「可迁移 / 只属于原作」两栏，凭记忆出特征等于没研究。
        主问题：
            "说 2–3 部你看完想立刻重看的片子或视频，每部说清打动你的具体是哪一口。"
        追问深化：
            用户说"像王家卫那种感觉" → 别当场从记忆里吐特征。你回："锚收下了，我先去查一遍它到底由什么构成、哪些搬得动。"研究完带两栏回来对："能给你的是霓虹湿反光、贴着墙走的狭窄构图、单一强调色统治画面；拿不走的是那套年代的镜头与冲洗味、明星脸自带的一半氛围、粤语旁白的语言节奏。可迁移这几样，哪一两样是你非要不可的？其余我来配。"
            用户报了片名说不出为什么 → 你回："哪个镜头让你按了暂停？描述那一帧里你看到什么。"
            用户拿跨片种参考，如给短剧找了塔可夫斯基 → 你回："借气质可以，借节奏不行。他那套长镜头搬进竖屏信息流就是划走率。你要他的什么气质，用你这个片种的手段怎么落？"
            用户给了参考图或截图 → 走 references/visual-style-spec.md 的 [参考图反推法]，反推完读回让用户点头哪些属性是承重的。
        接受标准：
            2–3 个正向参考，每个拆出承重属性；风格锚已研究并蒸馏成「可迁移 / 只属于原作」两栏、两栏已读回、只有用户确认承重的进了字段；跨片种参考只借气质不借结构；对参考片视觉事实不确定时已查证或标注。
        不接受的答案：
            "像 XX"被当字面规格照抄；说不出为什么的片名堆砌；把导演名当规格照抄——收下锚名却不做研究蒸馏，或蒸馏两栏是凭印象编的。
    2.2 · 反参考：
        覆盖意图：
            反例是边界桩。用户没态度，模型就按平均审美自由发挥，做出标准但平庸的 AI 味。
        主问题：
            "说 2 个你觉得 low 的 AI 视频或片子，具体哪里 low。刷到什么你会立刻划走？"
        追问深化：
            用户说"没什么不想要的" → 你回："那你就是没态度。塑料皮肤、每个镜头人脸都在换、游戏引擎质感的运动、贴图一样的假背景——这几样你都能忍？"
            用户说"别太花哨" → 你回："花哨等于什么？转场特效多？调色艳？运镜晃？给一个具体反例。"
        接受标准：
            至少 1 个具体反例 + 至少 3 条绝对不要——将编号为 NG，与叙事非目标共用编号序列。
        不接受的答案：
            "都行、没什么不要的"；"别太 AI"不拆症状。
    2.3 · 二选一定轴：
        覆盖意图：
            每个视觉轴用闭合二选逼方向，禁中间值。选一边能省掉下游几十条提示词的扯皮。
        主问题：
            每轴一个，给参考当锚，禁选中间：
            "质感：胶片颗粒，还是数字干净？"
            "色彩底：冷底还是暖底？强调色从哪来——画面里哪个真实物件发出这个颜色？"
            "光逻辑：自然光逻辑——光都有来源、敢让脸压进阴影，还是造型光——为美服务、光比自由？"
            "镜头性格：变形宽银幕的椭圆光斑和横向拉伸，还是球面镜头的干净规整？"
            "明度基调：整体压暗留高光，还是明亮通透？"
            "运动气质：稳——三脚架滑轨的静观，还是活——手持呼吸的跟随？"
            "表演气质：克制——情绪压在脸下面靠微表情走，还是外放——情绪写进动作和声音？"
        追问深化：
            用户选中间 → 你回："不许选中间。偏哪边？中间值到了提示词里就是模型自由发挥。"
            用户全都要 → 你回："全都要等于交给模型抽奖。分场景可以——日景数字干净、夜景胶片颗粒，但那是两条规则不是一条中庸，你要哪种？"
        接受标准：
            每轴一个明确方向值；强调色说得出框内真实来源；轴间不互相矛盾——矛盾已并到一起让用户取舍过。
        不接受的答案：
            任何轴选中间；"都要"不拆分场景规则；强调色凭空指定无框内来源。
    2.4 · 时代与世界锚：
        覆盖意图：
            时代即法律。不逐条钉死年代与世界设定，模型把一切拖回当代——"One extra holding a phone and the shot is gone."（一个群演掏出手机，这条就废了。）
        主问题：
            "故事发生在哪一年、什么地方？那个世界的科技水位到哪——有没有智能手机、什么车、什么招牌？"
        追问深化：
            用户说"无所谓，现代吧" → 你回："无所谓就是每条提示词各拍各的年代。钉死一个：2016 年冬、南方县城，店里挂旧年历、扫码牌是早期样式——具体到这个程度，模型才不会自作主张。"
            架空世界 → 你回："架空更要锚。这个世界的材质、交通、光源、文字长什么样？给我三个「一看就是这个世界」的标志物。"
        接受标准：
            年份或架空世界的等价设定 + 地理 + 科技水位 + 至少一句可逐字复用的锚句——锚句将进恒定层，逐条重复。
        不接受的答案：
            "现代、无所谓"；架空世界无标志物；年代只在脑子里没落成锚句。
    2.5 · 基准草案收拢：
        覆盖意图：
            把本 Phase 的全部拍板收拢成 visual-style.md 草案：字段表 + 两层基准文本。通用基准段逐字进每条动态提示词的恒定层与每张资产板开头；场域锚句按场域进对应场次的条与本场域内的场景板。两段合起来是全片风格的唯一执行载体。
        主问题：
            对内动作，不问用户：按 references/visual-style-spec.md 落字段、写通用基准段与场域锚句两段草案，然后逐段读给用户——通用基准段："全片每条提示词都会带着这段话，它就是你片子的妆面。读一遍，哪个词不对？"；场域锚句逐域读："这一句只跟着这几场走，别的场一个字都不带。这几件东西对吗？"
        追问深化：
            用户说"差不多就这样" → 你回："这段话要逐字复用几十次，现在改一个词是免费的，生成后改一个词是重拍。逐句过：质感这句对吗？色彩这句对吗？光这句对吗？"
        接受标准：
            字段表按 references/visual-style-spec.md [落盘骨架] 逐项有值，缺一不算齐；通用基准段成文且用户逐句过目；场域划分与每域一句场域锚句在案，未定处标 [待补充]、整段不许缺。
        不接受的答案：
            字段留空靠"生成时看情况"；两段基准文本没读回就落盘；只写一句总锚句让全片每条都带上。

[Phase 3 · 叙事范围与非目标]
    3.1 · 规模与范围：
        覆盖意图：
            定项目量级：单集还是多集、片长、场数量级——直接决定记忆层结构与生产预算，多集要建 series-outline。
        主问题：
            "单集还是系列？一集多长？现在的本子多少场？照一场约 2–5 条、一条 4–30 秒粗算——数值待实测校准——这个体量你烧得起几轮返工？"
        追问深化：
            用户说"先做一集试试，火了再说" → 你回："可以，但记忆层第一天就按多集设计——角色编号、场景资产、台账全部跨集不变。第二集开工时你会感谢今天。系列的大方向现在给我一句话。"
            用户片长与场数不匹配，如 3 分钟塞 15 场 → 你回："3 分钟 15 场，平均一场 12 秒，等于全片都是闪回节奏。砍场还是加长？"
        接受标准：
            单集/多集已定；片长与场数量级匹配；多集项目有集数与每集一句话方向，进 series-outline。
        不接受的答案：
            规模凭感觉；多集项目说不出集与集的关系。
    3.2 · 非目标与可实现性红线：
        覆盖意图：
            显式钉死不做什么。AI 视频另有一层：模型能力雷区要在范围层先砍，别等拆解时才发现拍不了。
        主问题：
            "这一版明确不做什么？给我至少 3 条故意不碰的东西。另外这几样是模型的雷区，你碰哪样：百人级群体动作、打斗长镜与器械操作这类连续复杂物理交互、长段精确口型、画面内清晰文字？"
        追问深化：
            用户说"都想要" → 你回："那就永远交不了片。雷区不是不能碰，是每碰一样，返工预算翻倍。哪样是这个故事非要不可的？其余写进非目标。"
            用户冒新点子 → 你回："这点子不错，记进停车场 PARK 编号，别丢，先把核心钉死。"
            用户说不出非目标 → 你回："如果只能保住一场戏，你保哪场？保不住的那些边缘欲望，就是非目标。"
        接受标准：
            至少 3 条显式非目标，落 NG 编号；雷区逐项过问、碰的已知代价、不碰的写入非目标。
        不接受的答案：
            "都要做"；没有任何不做清单；雷区没过问就放行。
    3.3 · P0 场次与优先级：
        覆盖意图：
            全 P0 等于没优先级。生成预算有限时，知道保哪场弃哪场。
        主问题：
            "哪几场是没有它这片子就不成立的 P0？预算或时间砍半，你先弃哪场？"
        追问深化：
            用户全标 P0 → 你回："全 P0 等于没优先级。只能保一场，留哪场？其余降 P1。"
        接受标准：
            P0 场次 ≤ 全片场数的一半；有明确的弃场顺序。
        不接受的答案：
            全 P0；说不出弃场顺序。

[Phase 4 · 一致性要求]
    【导演思维】第 3 问「一致性」的需求源头：这里定的等级，决定资产包的工作量与编译动态提示词时的锁定强度。
    4.1 · 核心角色一致性：
        覆盖意图：
            一致性有价签。核心角色要全套锁——三格角色表、声线锁、短串；一次性路人一句描述就够。分错级，要么白花资产工作量，要么主角换脸。
        主问题：
            "哪些角色跨场反复出现？给我一个出场次数排序。谁的脸绝对不能变？谁开口说话——要锁声线？谁会有状态变化——淋湿、受伤、换装？"
        追问深化：
            用户说"角色都要一致" → 你回："一致有价签。核心角色全套锁：角色表加声线锁加提示词短串；路人一句描述就够。谁值得上全套？超过 5 个核心角色，资产工作量翻倍，你确认？"
            用户遗漏状态变化 → 你回："他淋湿之后还有几场？状态即新资产——干身湿身是两个资产不是一个备注。现在数清楚，省得后面镜头里他自己晾干了。"
            用户要真人明星脸 → 你回："真人名字禁入提示词，平台直接拦。要那个味儿可以——拆成特征：年龄、骨相、气质、标志性的什么。你要的是「那个人」还是「那种人」？"
        接受标准：
            核心角色预判清单——正式编号归剧本拆解建的 reference-index——加每人一致性等级、开口者标声线需求、状态变化预判在案。
        不接受的答案：
            "都要一致"不分级；开口角色没标声线；已知的状态变化没登记。
    4.2 · 场景与道具一致性：
        覆盖意图：
            核心场景要角度覆盖与视觉锚点，叙事关键道具要状态分立。这里只做预判清单，设计归资产包三站。
        主问题：
            "哪几个场景反复出现？同一场景有没有日夜、天气差异？哪些道具是叙事关键——观众必须认出「还是那一件」的？"
        追问深化：
            用户说"场景就一个店" → 你回："一个店在你本子里出现了白天、雨夜、打烊后三种状态，那是三个场景资产。另外店里有没有一件东西，观众第三次看到它时应该心里一动？那件东西要单独锁。"
            道具有功能状态，如枪上膛、车损毁 → 你回："状态时序列出来：它在哪场是什么状态？状态即新资产，乱了就穿帮。"
        接受标准：
            核心场景清单含状态变体预判 + 叙事关键道具清单含状态时序预判。
        不接受的答案：
            场景不分状态；关键道具漏报；把车内饰和车外观当一个资产——它们各自成资产。
    4.3 · 声音基调：
        覆盖意图：
            声音四要素——台词与语气声线、音效、环境声、BGM 指令——全部以文字写入动态提示词；本站只定全片基调，句式与写法归 sound-writing。
        主问题：
            "台词密吗——两人一场平均几句？角色声音什么气质——音区、语速、口音方向？全片环境声底是什么？要不要配乐，什么方向？"
        追问深化：
            用户说"声音后面再说" → 你回："声线是一次定死逐字复用的书面条件，中途换措辞声音就漂。现在只要方向：他是低哑慢速还是清亮急促？一句话。"
        接受标准：
            台词密度方向 + 开口角色的声线气质方向 + 环境声底 + BGM 有无与方向。
        不接受的答案：
            "后面再说"；声线用"好听、有磁性"这类无方向词。
    4.4 · 合规与授权：
        覆盖意图：
            按片种定合规阈值，授权事实现在问清，别在交付时炸雷。红线与平台线详表归 review 的合规清单，本站采集事实与承诺。
        主问题：
            "片里有没有：真人肖像或声音——授权拿了吗、品牌标识、音乐版权素材、未成年人角色、暴力或擦边内容？发布平台的尺度线你了解吗？"
        追问深化：
            用户说"应该没事" → 你回："「应该」在交付那天不算数。逐项过：肖像、品牌、音乐、未成年人、尺度。有一项含糊就标待确认，阻塞交付。"
        接受标准：
            逐项有明确答案或 [待确认 · 阻塞] 标记；广告轨已确认品牌授权与竞品回避要求。
        不接受的答案：
            "应该没事"；广告轨不问品牌授权。

[Phase 5 · 每场情绪意图]
    第二层剧作审计的入口。完整模式逐场过；立项模式改为逐幕，配合 references/five-elements-audit.md 的立项清单。
    5.1 · 逐场意图：
        覆盖意图：
            每场一句"观众该感到什么"，是剧本拆解讲戏、分镜镜头表、审核预演的共同依据。意图空洞的场，下游只能瞎编。
        主问题：
            "这场戏，观众该感到什么？一句话。"
        追问深化：
            用户说"这场就是过渡一下" → 你回："过渡场是最贵的浪费。删掉这场，前后因果链断吗？不断，这场就不该花生成费；断，断的那一点才是这场的意图。"
            用户说的是剧情不是情绪，如"这场他发现了真相" → 你回："那是事件。观众看他发现真相时该是什么感受——替他怕？替他痛快？先他一步知道而揪心？"
            用户答不出 → 你回："这场戏的事件是什么——所有人共同经历的那一件事？沉默的那个人怎么参与？答出事件，情绪就在里面。"
        接受标准：
            每场一句情绪意图，可判定、互相有差异；连续三场同一情绪要过问节奏。
        不接受的答案：
            "过渡、铺垫"当意图；剧情复述当情绪；整片场场都"燃"。
    5.2 · 情绪曲线与判词轨迹：
        覆盖意图：
            单场意图连成全片曲线；观众对主角的判词变化即 value shift 轨迹，是曲线的深层线。两条线都要是设计过的，不是随机摇摆。
        主问题：
            "把全片的情绪走势画一条线：哪里最高、哪里最低、结尾落在哪？观众对主角的看法，从第一场到最后一场经历几次改判？"
        追问深化：
            曲线平的 → 你回："从头到尾一个情绪，观众在第几分钟走神？最高点在哪场？为了让它成为最高点，前面哪场要压下来？"
            判词只变一次 → 你回："只翻一次的人物是标签不是人。中间有没有一次「观众以为看透了他、又被打脸」？"
        接受标准：
            情绪曲线有起伏有落点；主角判词轨迹 ≥2 次变化且方向是递深不是摇摆。
        不接受的答案：
            曲线画不出来；判词从头到尾没变。
    5.3 · 审计触发与修复拍板：
        覆盖意图：
            意图逼完就有了审计的对照系。跑五元素审计，把结构弱点连同修复选项一起交用户拍板。
        主问题：
            对内动作：按 references/five-elements-audit.md 切 sequence、跑 CHAIN CHECK、报 WEAKEST POINT 与三档 WHAT IF；然后问用户："弱点在这，三个修法：一号只动最弱一点保你原稿，二号我给你个整场重写的方向，三号可选加法。选哪档，还是都不动？"
        追问深化：
            用户说"都挺好的吧" → 你回："审计不是商量。这个反转翻了情节但观众判词没动——「A reversal with no value shift is inert.」（没有价值转变的反转是死重。）死重的每一秒都在烧钱。你可以选「不修」，但要明白代价。"
        接受标准：
            审计结论呈现完毕；每个 WEAKEST POINT 有用户拍板，选档或明确不修；结论表、五元素要点存档与档位记入蓝图「剧作审计结论」，否掉的档位与理由记 decisions.md。
        不接受的答案：
            审计跳过；用户没拍板就落盘；把"不修"默默当成"没问题"——不修要记录为用户决策；只落一句"详情见对话"就把 CHAIN CHECK 判词丢在对话里。
