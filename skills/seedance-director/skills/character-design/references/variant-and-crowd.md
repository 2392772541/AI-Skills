---
name: variant-and-crowd
description: 当你判一个状态该不该升格成变体资产、要写蒙版点改的手术式编辑条、或要给一群人建群演资产时翻它。给出升格判据、全库唯一权威版的手术式编辑母版、变体编号与谱系规则、群演写法。
---

[定位]
    本卡管三件事：状态什么时候升格成变体资产，给判据；变体怎么做——蒙版点改 + 手术式编辑母版，本卡是该母版在全库的唯一权威版，prop-design 以路径引用本节；群演怎么写。
    底层公理：状态即资产，新版本永不覆盖旧版本；"Hold the face, change everything else."（脸不动，其余都可换。）

[状态升格判据]
    怎么认：
        升格为变体资产的条件——外观变化跨条持续且影响辨识：伤、湿、污、换装、发型剧变、位置绑定态，如「在驾驶舱内」这类高频复用的固定姿态坐位。判定问句：下一条还看得见这个变化吗？看得见 → 变体资产；只在本条内瞬时存在的表情、汗、短暂沾灰 → 留在动态提示词散文里，不建资产。
    认错长什么样：
        把湿身写成动态提示词里一句「他刚落水浑身湿透」——三条之后模型把他晾干了；反过来为一滴汗、一个皱眉建变体——资产库爆炸、索引失焦。
    典型例子：
        同一主角的干净版/落水湿身版/第三幕带伤版 = 三个资产，不是一个资产加备注；登记名如 `Mira (Episode 1 Base) (After shower)`、`Tank (injured)`，以及倒置重力镜头固化出的 `(inverted)` 状态资产——连为解决物理问题临时改造的输入图，都升格成正式资产。

[蒙版点改与手术式编辑母版]
    铁律：拿原版成图只改变化的部分，其余不动——图片从不整体过第二遍模型，皮肤与衣料纹理才能存活。"The base image stays the same pixels."（底图保持同一批像素。）新版本永不覆盖旧版本，旧图旧条目原样留档。
    手术式编辑母版，整条编辑链共用；编辑提示词允许结构化大写块，这是与生成提示词纯散文的合法区别。中英两式结构保留、逐块对应，项目语言默认中文：
    中文块，可整块抄：
        编辑这张图：{{一句目标}}。
        改动：{{唯一变化，精确描述}}。
        严格保留：{{穷举清单——脸、五官、肤质、发型、服装其余部分、姿态、背景、光线、构图、调色与颗粒}}。
        只改{{变化}}，其余 100% 不变。
    英文原句：
        Edit the image: {{一句目标}}.
        CHANGE: {{唯一变化，精确描述}}.
        PRESERVE EXACTLY: {{穷举清单：脸、五官、肤质、发型、服装其余部分、姿态、背景、光线、构图，以及调色/色板/颗粒}}.
        ONLY CHANGE: {{重申唯一变化}}. 100% identical otherwise.
    删除元素合法，但必须配填补物：「移除斗笠——露出原本的花白板寸」，不留空洞给模型即兴。
    教训："用户说你改多了 = 你锁得不够。"一次只改一件事；两处要改就编辑两轮。
    认错长什么样：
        变体重新生成整张——纹理全变、脸微漂，底图过了第二遍模型；CHANGE 块写了三件事；PRESERVE 只写「其他不变」四个字——穷举缺席，模型自由发挥；删除后不填补——空洞处长出随机物。

[变体编号与谱系]
    编号：char-NNN-vN，跨集不变；新状态 = 新变体，永不覆盖——全库常量。
    语义状态标签是登记字段用的人类可读检索键，叠加语法：`（装束线）（临时状态）[命运标签]`，层级为 装束线 → 临时状态 → 位置态，命运用方括号。例：「（EP1 基础装束）（雨夜湿身）」「（EP1 演出装）（淋浴后）」「[已阵亡]」——角色阵亡仍留档，命运标签防误用。
    谱系登记：每个变体在 reference-index 谱系字段写明父版本与变化点，可一路追溯到原版。例：char-001-v1 ← char-001：发全湿贴头皮 + 褂子透湿贴身 + 裤脚滴水。
    密版增量：变体的密版只写变化点 + 「其余同原版」，不重抄整套外观。
    返工反哺：retake 站改输入产生的倒置版、修复版这类新状态图，同样按此编号登记为新变体，不许游离在索引外——索引外的图不存在。
    认错长什么样：
        变体直接覆盖原编号——原版从此找不回；谱系字段空着——三个变体后没人说得清谁改自谁；变体密版重抄全套外观——与原版微差、成为第二真相源。

[群演写法]
    怎么认：
        人群是一个资产，不逐人建档。超过 15 人的人群模型会塌缩成三五个人形——所以群演资产写「身体的质量与局部」，不写人数：「挤在台口的身体、前景交叠的手臂、无清晰面孔的后景人影」。
    出图判定：
        需要被 @引用对齐、同一批人跨条出现的群演，出一张群体质感参考图——三四分之三视角中景、符合中灰底软光或该场场景光，画面中不许出现清晰可辨的脸；群演质感板是角色类板里唯一带环境的一张：只写人群所踩所倚的那一层承托面，石阶、廊下、摊位边，一两处即止，不搬 visual-style 的场域锚句、不铺陈设清单——铺开就成了半张场景板，与 scene-design 的板打架；脸源唯一性纪律对群演同样适用，群演图里的清晰脸会成为杂脸源。只出现一次的路人群不出图，纯文字登记短串 + 密版描述即可。
    编号：
        群演也走 char-NNN 与三态，建议编号段与具名角色隔开，如从 char-090 起；核心标记一律「边角」。
    服装与时代：
        群演的服装描述是时代最容易失守的地方——密版里按 00-bible/visual-style.md「时代与世界锚」的年份/地理与服装形制写死衣着范围，如「粗布短打与蓝灰工装，一律素面本色、手工缝制的直筒版型」，以正向穷举替代禁令。
    认错长什么样：
        写「37 名观众」——数字必塌缩 + 复制脸；为每个路人建四视——算力与索引双爆炸；群演图带清晰正脸——远景主角的脸开始像那个路人。

        见 examples/character-example.md 群演条。
