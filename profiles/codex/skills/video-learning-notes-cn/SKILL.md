# 视频学习笔记全流程

把视频处理成读者不看原视频也能系统学习、实践和复习的完整交付物。直接生成并验证真实文件，不停在计划、提示词、摘要或目录层级。

## 总原则

- 以原视频、原音频、课件画面和转录为证据源；不得根据文件名或常识编造课程内容。
- 保留讲师的解释顺序、推导、案例、有效问答、失败路径和判断依据，删除口头噪声与无关闲聊。
- 写成连续课堂叙事，而不是标题加几条短句。读者应获得接近听课的理解过程。
- 区分 `课程原话`、`结构化提炼`、`实操延伸`、`外部核验` 和 `待确认`。
- 用户给出目标目录时直接使用；涉及正式 Obsidian 笔记修改时，先确认活动 Vault，默认采用“预览 → 用户确认 → 正式写入”。用户已明确要求直接写入时可省略预览。

开始前完整读取 [完整融合课堂版标准.md](references/完整融合课堂版标准.md)。起草时读取 [输出结构模板.md](references/输出结构模板.md) 和 [内容关系图表选型.md](references/内容关系图表选型.md)，交付前读取 [质量验收清单.md](references/质量验收清单.md)。

## 1. 发现输入并建立工作区

1. 优先使用用户已经提供的附件或路径，不要求重复提供。
2. 确认源视频、输出目录、Obsidian Vault 根目录和已有同名笔记；按数字前缀和自然顺序排列多集课程。
3. 保留原文件，在 Vault 外建立工作目录：

```text
<course>_work/
  frames_1s/P01/
  keyframes/P01/
  audio/
  transcripts/
  ocr/
  report/
```

4. 运行 `ffprobe`，记录时长、分辨率、编码、帧率和音轨。先检查实际工具和脚本 `--help`，不要凭记忆拼参数。

## 2. 抽取并筛选视频证据

调用已安装的 `$build-video-course-notes`，复用其脚本：

- `scripts/select_keyframes.py`
- `scripts/ocr_keyframes.py`
- `scripts/transcribe_media.py`
- `scripts/validate_obsidian_note.py`

用 FFmpeg（音视频处理工具）每秒抽取一帧：

```powershell
ffmpeg -hide_banner -nostdin -y -i INPUT -vf fps=1 -q:v 2 OUTPUT\frame_%06d.jpg
```

筛选完整框架、表格、案例、操作步骤、界面状态和总结页。渐进展示的幻灯片优先保留最终完整状态；删除黑屏、转场、模糊帧、讲师重复露脸和近似重复图。

对至少三张高价值截图做原图视觉检查。截图必须记录来源集数、时间戳、画面含义和对应知识点。

## 3. 转写、OCR 与事实核验

抽取单声道 16 kHz WAV（适合语音识别的音频格式）：

```powershell
ffmpeg -hide_banner -nostdin -y -i INPUT -vn -ac 1 -ar 16000 -c:a pcm_s16le OUTPUT.wav
```

使用 faster-whisper（本地语音转文字工具）生成带时间戳的 JSON 和 Markdown；GPU（显卡加速）失败时检查真实 CUDA/DLL 报错，再改为 CPU，不能因为转写失败而虚构内容。对关键帧运行 OCR（图片文字识别），并交叉核对：

- 讲师发音与 ASR 转录；
- 课件原字与 OCR 结果；
- 人名、产品名、英文缩写、数字和因果关系；
- 相邻课程的重复页与上下文。

不确定内容先回听、看帧、查课件；仍不确定且属于公开可核验知识时，搜索官方文档或一手资料。外部资料只能用于核验或补充，必须附链接、访问日期并标为“外部核验/补充”。仍无法确认时使用：

```text
【待确认：原文“...”｜疑似“...”｜已检查：...｜仍缺：...】
```

## 4. 写成完整融合课堂版

调用 `$transcript-learning-system` 恢复课程结构，但不得把输出压缩成大纲。每个主要主题至少讲清：

1. 讲师为什么在这里讲它；
2. 概念是什么，用来解决什么问题；
3. 原理、步骤和判断依据；
4. 课程中的例子、演示或有效问答；
5. 怎样迁移到真实工作；
6. 什么时候不适用；
7. 常见坑、隐患、后果和规避办法；
8. 对应来源时间戳或截图。

不要使用固定字数比例衡量完整性。按主题覆盖审计：原材料中的主要主题必须在正文出现，或在“有意省略项”中写明原因。

## 5. 给小白解释术语

第一次出现英文缩写、产品名或专业词时，紧跟中文解释，至少说明“中文意思、用来干什么、为什么与当前内容有关”。例如：

```text
RAG（Retrieval-Augmented Generation，检索增强生成：先从资料库找证据，再让模型回答，用来降低脱离资料的胡编风险）
```

术语达到 5 个时增加“术语表”。正文首次解释后，后文可只使用简称。禁止用一串新术语解释另一个新术语。

## 6. 插入四类视觉材料

四类视觉材料职责必须分开，并在图注中明确标注。先理解内容关系，再决定是否画图，禁止把所有内容强行画成思维导图：

1. `原视频截图`：证明课程讲了什么，必须带集数与时间戳。
2. `AI 生成的小黑解释图`：解释概念、流程、对比、坑点；调用 `$ian-xiaohei-illustrations`。数量规划遵循“追上限，不追下限”：实质性长篇笔记默认完成 8 张，短笔记默认完成 3 张；先覆盖不同的高价值认知锚点，再判断是否需要超过默认上限。只有找不到新的非重复认知价值时才能少于默认数量，并在交付报告中写明理由。逐张生成并视觉检查，不能作为证据，也不能用重复构图凑数。
3. `AI 生成的内容关系图表`：调用 `$diagram-design`，按照 [内容关系图表选型.md](references/内容关系图表选型.md) 先判断关系，再从树状图、流程图、时间线、泳道图、系统结构图、层级图、循环图、象限图、数据流图等类型中选最合适的一种。图表用于解释关系，不证明课程事实；默认静态、minimal-light、`doc-wide`、`balanced`、`mixed`，每张同时交付可编辑 `.html` 和嵌入用 `.png`，并运行该 Skill 的 `self_check.py`。实质性课程默认 1–3 张不同职责的图表，若表格或正文更清楚则不强行画，并在交付报告说明。
4. `AI 生成的知识全景图`：只有整篇内容确实需要“一页总览”时才调用 `$article-to-knowledge-map`。长内容默认 12–18 个模块、6–12 个证据锚点，每个主要模块包含 2–5 个教学细节；同时交付 `.excalidraw` 和 `.png`。如果树状图、流程图、时间线或其他关系图已经比全景图更合适，可用关系图替代，但必须保留覆盖审计和选型理由。

在 Vault 中分别保存：

```text
assets/<course-slug>/source-screenshots/
assets/<course-slug>/illustrations/
assets/<course-slug>/diagrams/
assets/<course-slug>/knowledge-map/
```

使用 Vault 根目录 Wikilink，最终笔记不得出现绝对路径、`file://`、工作目录或临时帧名。

## 7. 形成可执行学习系统

除连续课堂正文外，必须产出：

- 学习目标与先修知识；
- 一张全局知识地图或关系说明；对实质性内容先做关系图表选型，必要时增加 1–3 张不同职责的图表；
- 可执行 SOP：输入、步骤、产物、验收标准和失败处理；
- 坑点与隐患表：触发条件、后果、识别信号、规避/补救；
- 可复用模板、检查表和主提示词；
- Recall（回忆型）与 Thinking（思考型）闪卡，每张只测一个知识点；
- 回忆、解释、对比、场景和实操题，并把答案折叠或后置；
- 待确认项、来源说明和覆盖审计。

多集课程生成 `00-课程索引.md`、每集 `Pxx-主题.md`、`复习题与闪卡.md` 和 `批处理验证报告.md`。多份长转录先做 1–2 篇样本供用户确认；样本已确认或用户要求直接批处理时，再分批完成全部文件。

## 8. 写入与验收

使用 Obsidian frontmatter、Wikilink、callout 和必要的 Mermaid。复杂关系优先使用 `$diagram-design` 的可编辑 HTML + PNG，不把 Mermaid 当成默认美术输出。不得静默覆盖冲突文件；先比较内容或哈希，再版本化命名。

依次运行：

1. `$build-video-course-notes` 的 `validate_obsidian_note.py`；
2. `$transcript-learning-system` 的 `validate_learning_note.py`；
3. [质量验收清单.md](references/质量验收清单.md) 的人工抽查。

验证失败就修复并重跑。只有当笔记存在、所有嵌入可解析、`missing embeds = 0`、图片可读、主要主题无遗漏、术语已解释且待确认项没有伪装成事实时，才报告完成。

## 交付口径

简洁报告：视频/课程数量与总时长、原始帧数、关键帧数、嵌入截图数、小黑图数、内容关系图表数与类型、全景图模块数、笔记与资产绝对路径、校验结果、遗漏审计结果、仍需人工确认的项目。不要只说“已处理”。
