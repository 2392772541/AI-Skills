description: 当审核发现要派修、而默认规则——回被审产物的生产站——不适用时翻它。只列默认之外的特殊路由；派活清单写进报告的发现清单，你照单派活零现场推理。
---

[默认规则]
    每条发现回被审产物的生产站修：拆解审回 script-breakdown——visual-style 定稿增量与索引骨架的发现同回它，定稿是它落的笔；资产审回对应设计站；镜头表审回 shot-design；成片审回 motion-compile。
    修复方回来只报"改了哪、在哪个文件"，不自宣 PASS——重审由你重新派 fresh film-reviewer。
    上游观察不派活——随下一个 ★确认 呈用户，用户拍板才走对应上游的再入协议。

[特殊路由 · 默认之外的全部例外]
| 情形 | 回哪 | 说明 |
|---|---|---|
| 死引用 · 资产该有而未产 | 对应设计站先产并登记 | 双出口之一；引用本不该存在则走默认，删改引用 |
| 死引用 · 控制图该有而未产 | control-image 先产落 05 | 控制图不进 reference-index |
| 工艺类发现——运镜/空间/表演/光/声音写法 | motion-compile 或 shot-design 收拢对应工艺卡重写该维度 | 工艺五卡永不直接派 |
| 账实不符 · 账错 | continuity 修 ledger，走变更记录 | 实错走默认回 motion-compile；两处都错各记一条 |
| 状态变体缺失——伤后仍绑无伤版一类 | 对应设计站补变体并登记 | 引用侧随后改绑 |
| 成品冒出核心级新资产 | script-breakdown 补清单，随后设计站补做 | 拆解遗漏 |
| 镜头表结构性矛盾被成片审发现 | shot-design 改表，经用户点头 | 结构改动必过用户；受影响条回 motion-compile 重编 |
| 红线命中 | 内容所在层的生产站；剧情设定层回 script-breakdown | 🔵 投放侧一律 user——手续与资质归用户，不派制作站、不改内容 |

[纪律]
    - 一个发现只派一个主出口；双出口的在改向里写明判断条件。
    - blocking 修完靶向重审该级；major/minor 照发现清单修，修完不重审、不阻塞下一步。
    - 发现清单的「状态」列追踪到底——待修 / 已修；随产物交确认前全部清账。
